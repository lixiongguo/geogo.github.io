# 实时推理加速工作记录

> 范围：`hik_realtime/hik_realtime_yolov8_seg.py`  
> 目标：缩短单帧墙钟时间、定位瓶颈，在保留实例分割 mask 的前提下提升实时性。  
> 启动：`python -m hik_realtime` 或 `python hik_realtime`

---

## 1. 已落地的加速手段

### 1.1 GPU + FP16 半精度推理

- 启动时通过 `resolve_infer_device()` 检测 CUDA。
- 有 GPU：默认 `device=0`、`half=True`；无 GPU：回退 CPU、`half=False`，打印告警不退出。
- CLI 可覆盖：
  - `--device auto|0|cpu`
  - `--half auto|true|false`
- `infer_yolo_seg(..., device=..., half=...)` 透传给 `model.predict`。
- **预期收益**：相对 CPU / FP32，seg 模型常见约 **1.5–2.5×**（视卡与 imgsz 而定）。

### 1.2 `model.fuse()` + Dummy 预热

- 加载权重后调用 `model.fuse()`，融合 Conv+BN，减少推理算子开销。
- 用与 `--imgsz` 一致的零图跑一次 `predict`，消除首帧编译/分配延迟，稳定显存驻留。
- **预期收益**：首帧延迟明显下降；稳态延迟更平滑。

### 1.3 预处理与推理解耦计时（避免重复预处理）

- 主循环先显式 `preprocess_for_inference`，再 `infer_yolo_seg(..., preprocess="off")`。
- 避免「外部已预处理、函数内部再 CLAHE」的重复计算，同时把 `pre` / `infer` 拆开便于 profiling。

### 1.4 可关闭的 Post / Draw（Pipeline 开关）

侧边栏 **Pipeline** 复选框：

| 开关 | 关闭时跳过 | 作用 |
|------|------------|------|
| Enable Post | overlap 合并、时间平滑、SDF | 对比后处理是否为瓶颈；关后 `post≈0` |
| Enable Draw | mask/框/质心叠加（含锁定瞄准绘制） | 对比可视化开销；关后 `draw≈0` |

用于 A/B：若关 Post 后 FPS 大幅上升，说明后处理值得优化；若几乎不变，则优先继续抠推理。

### 1.5 可调 `imgsz`（配置项，未改默认）

- 默认仍 **640**；CLI `--imgsz 416` / `320` 可进一步降算量。
- 由 profiling 数据决定是否下调，避免盲目牺牲检测质量。

## 2. Profiling / 观测手段（支撑后续优化）

### 2.1 分段计时

主循环 `_tick` 统计（ms）：

| 阶段 | 含义 |
|------|------|
| read | 相机取流 |
| pre | CLAHE 等预处理 |
| infer | YOLO `predict` + mask 回传 CPU |
| post | merge + smoother +（可选）SDF |
| draw | 分割叠加绘制 |
| total | 整帧墙钟 |

### 2.2 侧边栏「耗时 Profiling」

- 置顶醒目区块：TOTAL 大字、FPS、device/half。
- 各阶段 ms + 占比条；自动标红 **瓶颈** 阶段。
- 画面上不再叠 HUD，避免挡 ROI。

**使用建议**：先看瓶颈是 `infer` 还是 `post`；再决定下调 imgsz、关 SDF、或后续 TensorRT/流水线。

## 3. 明确未做 / 后续可选项

以下在计划文档中提及，**尚未实现**（等 profiling 数据再决定）：

- 多线程流水线（取流 / 推理 / 绘制并行）
- TensorRT / ONNX 导出加速
- 后处理 CUDA/CuPy 重写（SDF、mask 两两相交等）
- 默认下调 imgsz
- 去掉 mask、改 bbox 近似（已确认要保留 mask）

关于「后处理写 CUDA」：仅在 `post` 长期接近或超过 `infer`、且高分辨率多实例时才可能划算；优先用 Pipeline 开关与调 `merge_px` 验证。

## 5. 建议验证步骤

1. `python -m hik_realtime`，确认侧边栏显示 `dev:0 half:1`（有 GPU 时）。
2. 观察 Profiling：默认全开时 `infer` / `post` / `draw` 占比。
3. 关掉 Post、再关掉 Draw，分别记录 TOTAL / FPS。
4. 若 `infer` 仍是大头：试 `--imgsz 416`；仍不够再考虑 TensorRT 或流水线。
5. 若 `post` 是大头：减小 SDF `merge_px`，或默认关 SDF，再评估是否值得 GPU 化后处理。
