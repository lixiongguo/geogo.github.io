## 大型科学装置的自动化和数据

这篇文章主要论述了分布式控制系统对于大型科学装置的自动化和数据管理带来的好处，并且举了一些使用的案例。

新一代激光设施产生的数据量可能达到TB甚至PB级别，人工方法无法有效处理如此大规模的数据

**分布式控制系统提供了设备间的通信链路**

**传统模式**（图1a）：各子系统孤立运行，人工作为中心节点，依赖人工协调（如调整激光参数、诊断设备），难以适应高重频。

**现代化模式**（图1b）：通过分布式网络化控制系统实现设备间自动通信，人类仅负责高阶决策。

DRACO 激光装置的案例：

**DRACO 激光装置**（Dresden Laser Acceleration Source）是德国**赫尔姆霍兹-德累斯顿-罗森多夫研究中心**（Helmholtz-Zentrum Dresden-Rossendorf, **HZDR**）运行的一台**高功率、高重复频率的钛宝石**（Ti:Sapphire），主要用于**激光等离子体加速、高能量密度物理和新型辐射源开发**等前沿研究。

Draco激光装置的案例表明，对于许多现有高功率激光设施而言，向高重复频率运行的转型是一个**渐进过程**。关键在于认识到完全依赖人工协调的局限性，并开始有规划地**引入自动化接口和智能中间层**，逐步将人员从繁琐的重复性操作中解放出来，转向更高价值的决策和分析工作。

| -------------- | ---------------------- | ------------------------------------------------------------ |
|                | 实验室范围反馈控制回路 | 利用科学数据（如等离子体相互作用的测量结果）自动调整控制参数，实现更高重复频率、更少人为偏差的闭环优化。 |

|                | 学习曲线与灵活性不足   | 新控制系统可能因学习曲线陡峭而让用户感到不便，甚至阻碍创新。建议采用以人为本的设计，让开发者观察用户工作流程并持续改进软件。 |

|                | 遗留仪器集成           | 将现有（可能过时的）设备集成到新控制系统中存在困难，提出了开发驱动、使用适配层或维持其独立运行等解决方案。 |

## EPICS

EPICS (Experimental Physics and Industrial Control System) 

EPICS的典型应用是 Gemini激光控制系统

- **Central Laser Facility**（CLF）
  隶属于英国**科学技术设施委员会**（STFC），位于**卢瑟福·阿普尔顿实验室**（RAL），是英国国家级激光研究基础设施，为学术界和工业界提供多种先进激光平台。

- **Gemini 激光系统**

  - 是 CLF 运行的一台**超高强度、双光束皮秒钛宝石**（Ti:Sapphire）。

  - **峰值功率**：高达 **~2 × 0.5 PW**（即每束 0.5 拍瓦，共两束），聚焦强度可达 1021 W/cm21021 W/cm2 以上。

  - **用途**：用于**激光等离子体物理、电子/质子加速、实验室天体物理、高能量密度科学**等前沿研究

- **Gemini 激光控制系统**

  - 监控和控制激光器数千个硬件参数（如镜片位置、泵浦能量、真空状态、诊断设备）

  - 实现**实验自动化**（自动对准、能量优化、数据采集同步）

  - 保障**操作安全**（联锁、权限管理、故障诊断）

  - 提供**用户友好的操作界面**（供科学家远程或现场运行实验）

    

![image-20251014140507961](https://lgximgs.oss-cn-beijing.aliyuncs.com/images/image-20251014140507961.png)

EPICS包含两个主要部分IOC以及OPI

在EPICS（Experimental Physics and Industrial Control System）架构中，**IOC（Input/Output Controller）** 和 **OPI（Operator Interface）** 是两个核心组件，共同构成分布式控制系统的骨架。它们通过**Channel Access（CA）协议**实现通信（**在分布式控制系统中实时传输过程变量（Process Variable, PV）数据**），形成客户端-服务器模型。



### CA协议 vs. 传统工业协议（对比优势）

| 协议                    | 适用场景     | CA协议优势                                 |
| ----------------------- | ------------ | ------------------------------------------ |
| **Modbus**              | 工厂流水线   | 无实时性保障，数据量小（<100 PV）          |
| **OPC UA**              | 工业自动化   | 通用但缺乏科研级数据模型（如自定义PV结构） |
| **TCP/IP + 自定义协议** | 小型系统     | 需重复开发，难以标准化                     |
| **✅ CA协议**            | 大型科学设施 | **专为高可靠性、高并发控制设计**           |

### **Kafka 在 EPICS 中的核心作用**

1. **数据缓冲与异步处理**

   - **高吞吐量数据管道**：EPICS 的 IOC（Input/Output Controller）生成实时数据（如设备状态、传感器读数），通过 Kafka 作为消息队列缓冲数据，避免数据洪峰冲击后端系统。
   - **异步解耦**：生产者（IOC）将数据发布至 Kafka Topic，消费者（数据分析服务、数据库、可视化界面）按需订阅，实现 IOC 与数据处理模块的解耦，提升系统弹性。

2. **跨系统集成与协议转换**

   - 异构系统桥接

     ：Kafka 作为“数据总线”，连接 EPICS 与其他系统（如 Hadoop、Spark、时序数据库）。例如：

     - EPICS PVs（过程变量） → Kafka Producer → 实时流处理（Flink/Spark） → 可视化面板。
     - Kafka 支持多种协议适配器（如 MQTT、HTTP），可将非 EPICS 设备数据接入 EPICS 控制网络。

3. **实验数据流水线**

   - 同步辐射应用案例

     - **数据采集层**：IOC 从探测器（如 SIS3820 定标器）读取高频数据 → 发送至 Kafka Topic（如 `beamline_raw_data`）。

- **处理层**：流处理引擎消费 Kafka 数据，进行实时降噪、校准或特征提取。
  - **存储层**：处理结果写入 HDFS 或时序数据库（如 InfluxDB），供离线分析。

4. **容灾与数据持久化**

   - Kafka 的持久化机制（日志保留策略）确保实验数据不丢失，即使消费者服务宕机也可回溯数据。
   - 支持多副本机制，保障高可用性（如上海光源 BL07U 光束线数据备份）

NTP（Network Time Protocol）在EPICS（Experimental Physics and Industrial Control System）中的应用主要体现在为分布式控制系统提供高精度时间同步，确保实验设备、数据采集节点和操作界面的时间一致性。以下是其核心应用方向及技术实现

### 为何SSRF选择Bluesky Suite？

您的文档给出了明确答案：**“SSRF光束线控制系统主要基于EPICS。此外，Bluesky套件专为与EPICS接口而设计，并具备实验通用性。因此，我们采用Bluesky套件为SSRF二期光束线开发统一且通用的数据采集系统。”**

这个选择是**技术适配性和生态考量**的结果：

- **技术栈匹配**：SSRF的底层控制基于EPICS，而Bluesky是专为与EPICS无缝协作而设计的上层应用框架，集成成本最低。
- **Python生态优势**：基于Python的Bluesky更易于被科研人员接受和进行二次开发，与当今科学计算的主流生态（如NumPy, Pandas, Matplotlib, Scikit-learn）结合更紧密，便于后续数据分析和实现人工智能应用。

2.Material and Methods

整个数据采集系统的构建，从硬件组成到软件架构，再到具体的工作模块。其核心在于，如何将物理硬件、控制逻辑和用户操作无缝集成，构建一个高效、通用且自动化的数据采集平台。

### **一、硬件层设计：多通道同步采集架构**

#### **1. 信号探测与调理系统**

- ### **一、硬件层设计：多通道同步采集架构**

  #### **1. 信号探测与调理系统**

  - 5通道测量设计

    - 入射光子通量检测

      ：环形镜（TM）镀金表面（半切光状态）与洁净金网格双通道并行测量，互为校准

    - 样品信号采集

      ：标准样品电流（校准基准）、待测样品总电子产额（TEY）及荧光产额（TFY）三通道同步获取，支持表面与深层结构分析

  - 低噪声放大技术

    - 采用5台

      斯坦福SR570放大器，灵敏度覆盖1 pA/V至1 mA/V，实验设置为20 pA/V–100 nA/V，适配微弱电流信号

    - 配置12 dB/倍频程低通滤波器（截止频率30 Hz），有效抑制低温、磁场与真空设备噪声

    - 直流背景电流抑制：通过±1 pA至±1 nA的输入偏置电流调节消除干扰

该系统采用分层设计，确保了模块化和灵活性

1. **硬件层**：即上述的物理设备。
2. **控制层**：基于**EPICS**实现。运行在vxWorks系统上的IOC通过过程变量控制设备，而运行在CentOS系统上的操作界面通过Channel Access协议与IOC通信。
3. **数据采集层**：这是系统的核心，基于**Bluesky套件**（Python环境）开发。它通过**PyEpics**库与底层的EPICS控制层交互。其中，**Ophyd**库将硬件设备抽象为统一的Python对象（如电机、探测器），而**Bluesky运行引擎**则负责编排和执行复杂的实验流程。
4. **操作界面层**：基于**Control System Studio** 开发的图形用户界面，方便用户设置参数并实时监控实验。

**Control System Studio**（简称 **CS-Studio**）是一个**开源的、基于 Eclipse 平台的控制与监控系统开发环境**，专为**大型科学设施**（如粒子加速器、同步辐射光源、激光装置、核聚变装置等）设计。

### 核心定位

> **CS-Studio = EPICS 控制系统的“人机界面”**（HMI）

- **EPICS** 是一个用于构建分布式实时控制系统的**中间件框架**（定义数据模型、通信协议 CA/PCAS、数据库等）；

- CS-Studio

  则是在 EPICS 之上构建的

  图形化操作界面工具集

  ，让科学家和工程师能：

  - 实时监控设备状态（温度、压力、束流位置等）

- 远程操作设备（开关阀门、调节电源、启动序列）

  - 查看历史数据、报警信息、趋势图
  - 开发定制化控制面板（OPI：Operator Interface）

### 如何获取与使用？

- **官网**：https://controlsystemstudio.org
- **GitHub**：https://github.com/ControlSystemStudio
- **安装**：提供预编译版本（Windows/Linux）或通过 Eclipse Marketplace 安装插件；

通过将**EPICS的稳定控制能力**与**Bluesky套件的灵活实验编排和硬件抽象能力**相结合，并辅以用户友好的图形界面，为SSRF二期光束线构建了一个**统一、可扩展且高效**的数据采集系统。



3,4,5 总结与讨论

多通道同步测量具有三个优势：首先，它缩短了实验时间。其次，由于排除了入射光子通量不均匀性所引起的影响，实验结果受系统不确定性的影响更小。第三，通过查询标准样品峰位的理论值，可以减少光束能量校准的误差。
