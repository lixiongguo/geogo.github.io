# LangGraph + LlamaIndex 的采购审计 Agentic RAG 系统设计方案

## 1. 系统目标

构建面向中心采购场景的智能审计助手，实现：

-   采购数据查询
-   合同审查
-   价格合理性分析
-   供应商风险分析
-   制度合规检查
-   审计报告生成

核心思想：

> LangGraph 负责 Agent 状态管理与动态决策；
>
> LlamaIndex负责知识检索与数据连接； 
>
> MySQL/ES/Redis/MinIO 负责数据存储； 
>
> LLM根据当前 State 动态决定下一步动作。

------------------------------------------------------------------------

# 4. Agent设计

## 4.1 Supervisor Agent

职责：理解用户目标、初始化任务状态

例如：15万元购买高能绿色激光器是否合理？

输出：

``` json
{
  "goal":"采购合理性审计",
  "stage":"information_collection"
}
```

------------------------------------------------------------------------

## 4.2 Decision Agent（核心）

根据当前State动态选择下一步动作。

可选择：

-   query_purchase_database（）：查询采购结构化数据（合同、设备、价格、数量、供应商等）。
2. retrieve_documents（）：检索中心知识库（合同、制度、技术规范、审计报告等）。
3. read_original_document（）：读取原始文档内容，用于证据核验。
4. analyze_purchase_excel（）：对采购Excel数据查询，完成统计与分析。
5. analyze_price_reasonableness（）：分析采购价格合理性，计算价格偏差和风险。
6. generate_audit_report（）：根据审计结果生成结构化报告。
-   finish （完成）

示例：

当前状态：

``` json
{
 "evidence":[
   "历史价格14万元"
 ],
 "missing_information":[
   "技术规范",
   "采购制度"
 ]
}
```

Agent判断：

``` json
{
 "next_action":"query_purchase_database"
}
```

------------------------------------------------------------------------

## 4.3 SQL Agent

负责：根据当前完成状态，选择某一个或者多个MYSQL数据库的表中，查询设备的采购合同编号、供应商、设备名称、设备型号、价格、数量、总价、设备备注。

数据来源：MySQL。

------------------------------------------------------------------------

## 4.4 Retrieval Agent

根据当前状态，调用 LlamaIndex对知识进行检索：

    Query
    ↓
    LlamaIndex Retriever
    ↓
    ES Vector Search
    ↓
    Rerank
    ↓
    Context

知识：

-   合同正文
-   历史审计报告

------------------------------------------------------------------------

## 4.5 Audit Reasoning Agent

综合查询到的：

-   历史价格
-   设备参数
-   当前报价
-   合同内容

输出：

-   是否合理
-   审计依据

------------------------------------------------------------------------

## 4.6 Report Agent

根据当前的内容，生成：

-   审计结论
-   数据依据
-   复核建议

------------------------------------------------------------------------

# 5. State设计

``` python
class AuditState:
    question:str # 用户问题，用户提出的原始问题
    goal:str # 任务目标，Agent最终完成的目标
    stage:str # 当前阶段，当前任务执行到哪个阶段
    evidence:list # 当前证据，保存已经获取的信息、数据、文档依据
    missing_information:list # 缺失的信息，记录当前还需要补充的数据或资料
    executed_tools:list # 已执行的工具，记录Agent已经调用过的工具
    analysis:str # 分析结果，保存当前阶段的推理或分析内容
    next_action:str # 下一步动作，记录Agent决定下一步执行动作
    finished:bool # 任务是否完成，判断整个任务是否结束
```

State表示Agent处理当前任务的状态，Agent根据当前的State判断下一步。

------------------------------------------------------------------------

# 6. 动态执行流程

示例问题：

> 准备购买15万元高能绿色激光器，是否合理？

示例执行：

    用户问题
    ↓
    Supervisor Agent
    ↓
    初始化State
    ↓
    Decision Agent
    ↓
    查询历史价格
    ↓
    更新State
    ↓
    Decision Agent
    ↓
    检索采购制度、合同文件、技术规范
    ↓
    更新State
    ↓
    Audit Agent
    ↓
    Report Agent
    ↓
    输出报告

而不是提前定义：

    问题A -> 固定流程A

而是：

    观察当前状态
          ↓
    决定下一动作

# 7. LlamaIndex作用

## 7.1 LlamaIndex负责：

-   文档接入
-   Node切分
-   Embedding
-   Retriever
-   RAG查询

流程：

    - 文档接入（Document Loading）
    	将各种非结构化数据转换为 LlamaIndex 可处理的 Document 对象。
    - 文档结构化处理
    - Node切分（Chunking）
    	将完整Document拆分为适合LLM检索的小知识单元。
    - Embedding向量化
    - 索引构建（Index）
    - Retriever检索
    - RAG查询与上下文组织
    	将检索结果提供给LLM，让LLM基于检索的知识回答。

# 8. Excel处理方案

Excel不直接全部向量化。

采用双通道：

## 数据通道

```
Excel
↓
MinIO保存原文件
↓
Parser解析
↓
识别：Sheet、字段、数据类型、业务含义
↓
生成两个结果
+----------------+
|                |
业务数据         表结构描述
|                |
MySQL            ES
```

Mysql保存：采购订单合同编号、供应商、设备名称、型号、数量、单价、总价、备注等等；

MinIO保存：原始文件

## 语义通道

每张表生成一个 Schema Document。

```
{
"table_name":
"purchase_order",
"description":
    "
    采购订单表。记录企业采购设备的订单信息，包括设备名称、合同编号、采购数量、采购单价、采购金额、供应商和采购时间。
    适用于查询：购买了哪种设备、采购数量、采购金额、历史采购记录。
    ",
"columns":[
    "contract_no",
    "equipment_name",
    "quantity",
    "unit_price",
    "total_price",
    "supplier"
    ]
}
```

保存：表结构描述、字段含义、数据说明

进入：ES + LlamaIndex。

作用：帮助Agent找到正确的数据表。

7. retrieve_database_schema：根据用户问题寻找最可能的数据表。
我们只需要定义：TOOL名称、TOOL作用描述、参数结构（Schema）、TOOL执行逻辑。
在LangGraph+Tool Calling Agent模式下，Tool函数的参数通常不是人工提前填写，而是由Agent（准确说是LLM）根据当前用户问题和State自动生成，然后传递给Tool。

    """
    作用：结构化数据查询工具
    查询采购业务数据库中的结构化数据。
    用于获取确定性的业务事实数据，例如：历史采购记录、合同编号、设备名称、采购数量、单价、总金额、供应商信息、设备备注等等。
    当用户询问：买过哪些设备？某设备采购多少钱？某供应商采购金额？历史采购数量？等问题时，应优先调用此工具。
    不用于：查询合同正文内容查询采购制度查询技术规范。
    输入：符合数据库结构的SQL查询语句。
    输出：查询结果列表。
    """
    
@tool
def retrieve_documents(query:str):

    作用：从知识库中检索相关文档

    当用户问题涉及：为什么、是否符合规定、技术要求是什么、合同有什么约束、历史经验、合同日期等与合同相关内容时应调用此工具。
    不用于：查询具体采购金额、查询数量统计、查询排名
    输入：需要检索的自然语言问题。
    输出：返回相关知识片段：
    {
      document,
      page,
      content,
      metadata
    }
    """
    
@tool
def read_original_document(document_id:int,page:int):
    """
    作用：读取文档原始内容
    用于：查看合同原文、获取指定PDF页面、验证检索结果、获取表格上下文等内容，当需要确认原始证据时调用。
    不用于：普通知识查询、数据统计
    输入：document_id、page
    输出：页面文本、图片、表格内容
    """
    
@tool
def analyze_purchase_excel(file_id:int,question:str):
    """
    统计采购Excel文件中的数据。
    用于：Excel统计；

    不用于：查询合同条款、查询制度文件
    输入：file_id、question
    输出：统计结果或分析结果。
    """
    
@tool
def analyze_price_reasonableness(current_price:float,historical_prices:list):
    """
    分析采购价格合理性。
    用于：判断报价是否异常、比较历史价格、计算价格偏差

    输出：平均价格、最大价格、最小价格、偏差比例、风险等级

    """
    
@tool
def generate_audit_report(evidence:list,conclusion:str):

    输出： 
    结构化报告：
    - 审计结论
    - 数据依据

    注意：不负责检索数据，不负责计算。
    """
