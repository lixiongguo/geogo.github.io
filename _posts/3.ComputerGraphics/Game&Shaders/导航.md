游戏中的图的搜索算法有两种

\1. 非启发搜索，即在所要搜索的图的边是没有开销。而一般图的遍历或者是查找图中两个节点间的路径仅仅是需要区分已访问的节点和未被访问的节点以及指派一个目标节点，而这类图是拥有这些信息的。具有代表性的盲目搜索算法包括：深度优先算法和广度优先算法。另一种常见的搜索也是本游戏中图的搜索算法是基于开销的图搜索算法，其所对应的图将会有一个开销，开销与所通过的边相关联。例如，导航图的边通常都会有一个与边连接的两个节点的距离成比例的开销。虽然此类搜索可以通过盲目搜索所有的路径然后再分别求出各条路径间的开销进行对比求出最优路径，但这显然不是高效的算法。

\2. 另一种方法是启发式搜索，采用边放松(Edge Relax)技术即在一个算法运行的时候，它从源节点到抵达目标节点路径上的所有其他节点中搜集当前最优路径(Best Path Found So Far即BPSF)信息。这个信息在检查新的边时得到更新。如果刚检查的边表明，如果通过此边到达一个节点的路径取代现有的最优路径会使路程更短，那么，这条边就被加入，而路径也相应地更新了。这个过程就像沿着BPSF的边伸展的一根橡皮筋，在找到一条更短的路径时，被拉紧的橡皮筋就放松了一点[5]。要实现边放松技术有就要用到最短路径树结构(Shortest Path Tree,即SPT)是图G的一棵子树，它代表了从SPT上的任何节点到达源节点的最短路径。

边放松的搜索算法包括了Dijkstra与A*算法，此两类算法在游戏中作为怪物AI寻路组件的核心算法，其着极大的作用。

Dijkstra算法每一次构造最短路径树的一条边，如果有目标节点则可以搜索到目标节点后终止，否则算法最终构造出一颗图G的SPT。游戏中的寻路组件是基于A*算法实现的，游戏的A*算法实现又是基于Dijkstra算法的实现。

Dijkstra算法通过最小化开销进行搜索。在对搜索边界上的点进行处理的时候，如果估算一下它们距离目标节点的开销并作为下一步的参考，这样就有望大大提高算法的效率。

A*算法对搜索边界上的点的开销的计算是不同的。被修正的到节点的开销F用来决定节点在优先队列中的位置，F是这样计算的。

### 2.6.2导航图的构造

对游戏中的地图要用到上面介绍的图的搜索算法，那就需要通过某种方法将游戏中地图转化为数据结构中的图结构。常用的方法包括：基于单元的方法、基于可视点的方法。具体使用哪种方法要根据游戏中场景的需求来决定。

基于单元的导航图：基于单元的导航图即是将原地图平均划分为个格子，每个格子即是导航图中的一个节点，节点的相邻关系即是导航图的相邻关系。这种方法的优点是导航图的信息可以根据原地图的特点进行细致的逐个格子的定制。但是缺点是图的规模随着划分的精细程度提高，导航图的复杂图急剧增大，即使是一个的小单元地图，组成这幅地图将需要10000个节点和大约78000条边。对于某些战略类游戏，同时有数百个AI单元在地图中活动，每个更新就需要进行图形搜索，这会造成相当大的时间消耗，另外空间消耗也是相当巨大的。

通过安置节点的方法，可以创建可视点导航图(POV)，通过手工安置环境中的一些重要点，例如到其他节点有视线的图节点来构造导航图。POV图的一个重要优点是易于被扩展去包含一些节点，这些节点能提供信息以及其上的连通数据。这些节点可以是在游戏有一定代表意义的点。如理想的阻击掩护体或伏击位置。它的缺点是需要地图设计者花费许多宝贵的时间去定位和调整这个游戏地图。

寻路模块是游戏中的基础模块，其主要由两部分组成：导航图的构造与图的搜索算法。根据游戏的需求对这两个模块采用适当的设计，本游戏的寻路模块概要设计如下。

（一）AI系统寻路算法设计

AI系统所采用的寻路算法依使用的情况分为两种：A*算法与Dijkstra算法。当AI智能体要寻找的对象一个单一的目标时，则使用A*算法。因为A*算法能根据启发因子给出的信息更加有针对性的寻找目标，从而图的搜索次数能够降低搜索的效率更高。而当AI智能体要寻找的对象是一个物品类，在本游戏中是药品和武器，则所采用的寻路算法是Dijkstra算法，因为Dijkstra算法最终可以得到一颗图的最短路径树(SPT)从而能够找到当前离AI智能体最近的此类物品实例的位置。

（二）AI系统导航图构建方式

AI系统使用的导航图构建方式是使用基于可视点的导航图。这主要是考虑到一方面本游戏的场景丰富，需要在游戏中安插多个有意义的点。另一方面是由于本游戏部分场景规模庞大，如果采用基于网格的导航图构建将会造成导航图占用资源过多，在手机这种资源紧俏的平台上，这种方法是不可行的。本游戏中导航节点的安置的工作是由游戏的策划人员完成的，而导航图整体的制作是由美术人员完成的。

（二）A*算法的启发因子设计

本游戏的A*算法的启发因子采用的是欧式距离，这主要是考虑到本游戏的地图空间是一种连续的空间。欧式距离是度量此类空间中两点距离的最自然也是最简单的方式。为了尽量节约计算资源，在本游戏中欧式距离的计算是两点间距离的平方值。

（一）A*算法

本游戏A*搜索算法通过使用一个基于索引的优先级队列来实现。一个优先级队列，是一个按照元素优先级对元素进行排序的队列。这种类型的数据结构可以用来存储边界所指向的节点，由它们距离源节点的开销递增顺序来决定存储的顺序。使用此方法保证了排在优先级队列前面的节点既是在SPT中没有的，又是到达源节点的开销最小的节点。

一个优先级队列必须能使内的元素按照指定的顺序进行存放。这意味着每一个图的节点必须有一个额外的数据成员用于累加到那个节点的开销，为做到这点或许会大量使用比较操作符才能实现正确的行为。尽管使用一个额外的变量的确是一个有效的方法。然而这会改变已有的图节点，此外，这样做在多个搜索同时运行时会带来问题，因为每一个搜索都会使用同一个数据。虽然可以通过创建节点的多个副本来克服，但是宝贵的内存和速度都丧失了。

为克服以上问题本游戏采用另一种方法即使用一个索引的优先队列。这种队列用一个键值动态数组来进行索引，键是每一个节点累加的开销，它们保存在动态数组中。一个节点通过插入它的索引加入队列。类似地，当从索引优先队列进行检索时返回的是节点的索引而不是节点本身。

（二）寻路组件的时间片规划算法

对于寻路算法一个可以为CPU减轻负担的方法，就是给每个更新步骤中所有搜索请求都分配一定数量的CPU资源，并且在这些搜索之间平均地分配这些资源。通过把这些搜索分成多个时间步骤，这是可以达到的。这种技术是参考操作系统中的CPU“时间片轮转算法”。

随着智能体请求的搜索，路径规划器会创建相关的搜索(A*或Dijkstra)的实例，并用一个路径管理类注册。路径管理器保存所有活跃的路径规划器指针表，路径管理器保存所有活跃的路径规划器指针表，并且拥有一个搜索周期的总和其值即为每次更新时完成的搜索时间片任务。当一个搜索或是顺利地完成，或没有找到一条路径，路径规划器发送消息通知发出搜索请求的智能体。这个过程的UML序列图如图5-2所示。

一个A*搜索算法和一个Dijkstra搜索算法包含一个循环，不断地重发以下的步骤。

\1. 从优先队列中找到下一节点。

\2. 添加此节点到最短路径树

\3. 检测这个节点，看它是不是目标

\4. 如果节点不是目标节点，检查和这个节点相连接的节点，如果合适，把它们放到优先队列中去。如果这个节点是目标节点则成功返回

将这些步骤的一次重复作为一个搜索周期，重复多次搜索周期将完成一次搜索，搜索周期可以用来把一个搜索分成多个时间步骤，每个时间步骤分配一个时间片，从而达到类似时间片轮转的效果。

另一种降低CPU消耗的方法是分层路径寻找。每次路径查找都是逐层进行的。先从大的空间范围开始逐步细化直到找到目标。比如要构建一个国家范围内两点的路径搜索，则可以这样进行分层搜索：先从省级，然后是市级，再然后是县级，不断细化直到搜索到路径。
