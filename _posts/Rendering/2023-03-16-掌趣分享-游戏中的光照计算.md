PBR（Physically Based Rendering，基于物理的渲染）是一组基于真实世界光学物理规律的渲染技术。相比传统的 Phong / Blinn-Phong 经验模型，PBR 使用更符合物理的光照模型，使得材质在不同光照环境下表现一致且自然。

## 1. 传统渲染工作流 vs PBR 工作流

「工作流」指的是：美术如何定义材质、用哪些贴图、这些贴图如何进入着色器。传统渲染与 PBR 的核心差别，不只是公式不同，而是**材质参数是否与光照解耦**。

### 1.1 传统工作流（Phong / Blinn-Phong）

传统管线常见贴图与参数：

| 贴图 / 参数 | 含义 |
|:---|:---|
| **Diffuse Map** | 漫反射颜色（常混入阴影、脏迹、甚至环境光） |
| **Specular Map** | 高光强度 / 颜色（经验系数） |
| **Shininess / Gloss** | 高光锐利程度（无明确物理含义） |
| **Ambient / Emissive** | 环境光与自发光（经验叠加） |

着色近似为：

```
color = ambient
      + diffuse * max(N·L, 0)
      + specular * pow(max(N·H, 0), shininess)
```

问题在于：参数是**为当前光照调出来的**。换一套 HDRI 或主光强度，同一套材质往往要重新调参，否则过曝、发灰或不协调。

### 1.2 PBR 工作流

PBR 要求贴图尽量只描述**表面本身的物理属性**，光照由着色器按能量守恒计算：

| 维度 | 传统工作流 | PBR 工作流 |
|:---|:---|:---|
| **理论基础** | 经验公式 | 辐射度量学 + 微平面 BRDF |
| **参数含义** | ambient / diffuse / specular / shininess | albedo、metallic / specular、roughness / glossiness |
| **贴图内容** | 常含烘焙光影、假高光 | 尽量不含光照信息（纯材质） |
| **光照适应性** | 换光环境需重调材质 | 同一材质在不同光照下仍合理 |
| **能量守恒** | 无保证 | 出射 ≤ 入射 |
| **对美术经验** | 依赖「在这套光下怎么拧好看」的经验 | 参数有物理含义，可按参考区间调，门槛更低 |
| **模型拓展** | 加效果常另起一套经验项 | 同一 $f_r$ 框架上叠 lobe（清漆、绒毛、透射等） |
| **美术目标** | 「在这套光下好看」 | 「材质对，光变了也成立」 |

一句话对比：

> **传统工作流调的是「在当前光照下的最终样子」；PBR 工作流调的是「材质本身」，光照交给引擎。**

因此有两点工程上很重要的好处：

1. **对美术经验要求更低**：不必为每种灯光手调 shininess / specular；按 albedo、金属度、粗糙度等有物理含义的量（及参考色板）即可得到跨场景可用的材质。风格化、可读性上的取舍仍在，但「拧到不穿帮」的门槛明显下降。
2. **着色模型易于拓展**：Clearcoat、Sheen、Transmission 等是在同一套微平面 + 能量守恒框架上加 lobe，而不是再发明一套互不相容的经验公式。

这也是为什么 PBR 能让同一资产在编辑器、运行时、不同关卡灯光下保持观感一致，并方便引擎持续加新材质特性。

## 2. PBR 有哪些工作流

PBR 在美术与引擎侧，主流有两条并行工作流。它们描述的是**同一套物理现象**，差别主要在贴图拆分方式与可控粒度。

```
传统 Phong/Blinn
        │
        ▼
     PBR 材质工作流
   ┌────────┴────────┐
   │                 │
金属度-粗糙度      高光-光泽度
(Metal/Rough)    (Spec/Gloss)
   │                 │
   └────────┬────────┘
            ▼
   Cook-Torrance 等物理着色
```

### 2.1 金属度-粗糙度（Metalness-Roughness）

当前游戏与实时渲染最主流（Disney / UE / Unity / glTF 默认）。

| 贴图 | 含义 |
|:---|:---|
| **Albedo / Base Color** | 非金属 = 漫反射颜色；金属 = 镜面反射颜色 |
| **Metallic** | 0 = 非金属，1 = 金属（多数情况二值） |
| **Roughness** | 0 = 光滑镜面，1 = 粗糙漫射 |

核心约定：

| 属性 | 非金属 | 金属 |
|:---|:---|:---|
| **$F_0$** | 约 0.04（近似常数） | 来自 albedo 的 RGB（约 0.5~1.0） |
| **漫反射** | 有（albedo） | 无（$k_d = 0$） |
| **镜面高光颜色** | 近似无色 | 有色（来自 albedo） |

优点：贴图省（Metallic / Roughness 多为单通道）、不易调出非物理结果、引擎支持最好。  
代价：非金属的 $F_0$ 默认固定，有色高光（某些宝石、特殊涂层）不好直接表达。

### 核心参数

| 参数                    | 含义                   | 取值          | 贴图          |
| :---------------------- | :--------------------- | :------------ | :------------ |
| **Albedo / Base Color** | 基础颜色（无光照信息） | RGB [0,1]     | Albedo Map    |
| **Metallic**            | 是否金属               | 0 / 1（为主） | Metallic Map  |
| **Roughness**           | 粗糙度                 | 0~1           | Roughness Map |
| **AO**                  | 环境光遮蔽             | [0,1]         | AO Map        |
| **Normal**              | 法线扰动               | RGB→XYZ       | Normal Map    |

### 可选参数

| 参数                      | 用途                     |
| :------------------------ | :----------------------- |
| **Emissive**              | 自发光（方程中的 $L_e$） |
| **Height / Displacement** | 视差 / 曲面细分          |
| **Opacity**               | 半透明                   |
| **Clearcoat**             | 车漆、钢琴漆             |
| **Sheen**                 | 布料边缘                 |
| **Transmission / IOR**    | 玻璃、水及非金属 $F_0$   |



### 2.2 高光-光泽度（Specular-Glossiness）

更接近「传统 Specular 贴图」思路，但参数仍服从能量守恒。

| 贴图 | 含义 |
|:---|:---|
| **Diffuse / Albedo** | 漫反射颜色（金属通常接近黑） |
| **Specular** | **RGB**：镜面反射颜色与强度（金属、非金属都可有色） |
| **Glossiness** | 光泽度；与 Roughness **互为反相**（`roughness ≈ 1 - glossiness`） |

优点：非金属也可单独控制反射色与强度，艺术自由度更高；金属/非金属过渡处有时可减少金属度工作流的插值伪影。  
代价：Specular 是 RGB，占更多贴图内存；更容易调出能量不守恒的参数；实时引擎与 glTF 主线正逐渐以 Metal/Rough 为主（spec/gloss 多为扩展或离线资产）。

### 2.3 如何选择

| 场景 | 更合适的工作流 |
|:---|:---|
| 手游 / 实时游戏、UE/Unity 标准材质 | **Metalness-Roughness** |
| 需要精细控制非金属反射色 | Specular-Glossiness（或 Metal/Rough + Specular/IOR 扩展） |
| 从旧 Specular 资产迁移 | 可先 Spec/Gloss，再烘焙/转换到 Metal/Rough |

两条工作流可以互相转换（Roughness ↔ Glossiness 取反；Metal/Rough 的 albedo+metallic 与 Spec/Gloss 的 diffuse+specular 存在近似映射），但边界材质（半金属、脏迹金属）转换并非总是无损。

下文公式与伪代码默认按 **Metalness-Roughness** 展开——它是实时游戏里最常见的那条。





## 3. 渲染方程（Rendering Equation）

PBR 着色的理论基础是 Kajiya（1986）提出的渲染方程。完整形式包含自发光与反射两项：

$$
L_o(\mathbf{p}, \omega_o) = L_e(\mathbf{p}, \omega_o) + \int_{\Omega^+} f_r(\mathbf{p}, \omega_i, \omega_o) \cdot L_i(\mathbf{p}, \omega_i) \cdot (\mathbf{n} \cdot \omega_i) \, d\omega_i
$$

| 符号 | 含义 |
|:---|:---|
| $L_o(\mathbf{p}, \omega_o)$ | 点 $\mathbf{p}$ 沿观察方向 $\omega_o$ 的出射辐射率 |
| $L_e(\mathbf{p}, \omega_o)$ | 表面自身发出的辐射率（自发光 / emissive） |
| $L_i(\mathbf{p}, \omega_i)$ | 沿入射方向 $\omega_i$ 的入射辐射率 |
| $f_r(\mathbf{p}, \omega_i, \omega_o)$ | BRDF（双向反射分布函数） |
| $\mathbf{n} \cdot \omega_i$ | 余弦项（Lambert 定律） |
| $\Omega^+$ | 上半球面 |

> 渲染方程在问：**点 $\mathbf{p}$ 沿方向 $\omega_o$ 出射了多少光？** 答案是：**自身发出的光** $L_e$，加上所有入射光经 BRDF 反射后的积分。

只讨论不发光表面时，常省略 $L_e$（即 $L_e = 0$），文章后文伪代码里的 `Lo += params.emissive` 对应的就是这一项。

### 3.1 递归展开：直接光与各阶间接光

关键在于：$L_i$ 不是「凭空存在」的。沿 $\omega_i$ 看到的入射光，来自别的表面（或光源）的出射光：

$$
L_i(\mathbf{p}, \omega_i) = L_o(\mathbf{p}'\!, -\omega_i)
$$

其中 $\mathbf{p}'$ 是从 $\mathbf{p}$ 沿 $\omega_i$ 射线击中的下一个点。于是渲染方程是**关于 $L_o$ 的递归积分方程**，可按「弹射次数」展开成 Neumann 级数：

$$
L_o = L^{(0)} + L^{(1)} + L^{(2)} + L^{(3)} + \cdots
$$

| 项 | 光路（从光源到眼睛） | 含义 |
|:---|:---|:---|
| $L^{(0)} = L_e$ | 发光体 → 相机 | 直接看见光源 / 自发光 |
| $L^{(1)}$ | 光源 → 表面 → 相机 | **直接光照**（Direct Lighting） |
| $L^{(2)}$ | 光源 → 表面 → 表面 → 相机 | **一阶间接光**（1-bounce GI） |
| $L^{(3)}$ | 再多一次弹射 | **二阶间接光** |
| $\cdots$ | 更长路径 | 更高阶全局光照 |

示意：

```
L^(0)  自发光 / 直视光源
         Le ──► 相机

L^(1)  直接光照
         光源 ──► p ──► 相机

L^(2)  一阶间接
         光源 ──► p' ──► p ──► 相机

L^(3)  二阶间接
         光源 ──► p'' ──► p' ──► p ──► 相机
```

把入射拆成「来自光源」与「来自其他表面」，反射积分也可写成：

$$
\int_{\Omega^+} \cdots \, L_i \, d\omega_i
\;=\;
\underbrace{\int_{\Omega_{\text{light}}} \cdots \, L_{\text{light}} \, d\omega_i}_{\text{直接光 } L^{(1)}}
\;+\;
\underbrace{\int_{\Omega_{\text{surf}}} \cdots \, L_o(\mathbf{p}',-\omega_i) \, d\omega_i}_{\text{间接光 } L^{(2)}+L^{(3)}+\cdots}
$$

现实中级数无穷，能量随弹射衰减，工程上截断或近似：

| 做法 | 通常包含 | 常见于 |
|:---|:---|:---|
| 实时前向/延迟着色 + 点/方向光 | $L_e + L^{(1)}$ | 手游、主机基础管线 |
| + IBL / 环境贴图 | 用预滤波环境光近似大量间接 | 多数 PBR 实时引擎 |
| + SSAO / SSGI / Reflection | 屏幕空间补一阶间接的一部分 | 中高端实时 |
| + 光照贴图 / Light Probe / Lumen 等 | 烘焙或缓存多阶间接 | 主机 / PC |
| 路径追踪（Path Tracing） | 蒙特卡洛采样多阶路径 | 离线、部分次世代实时 |

后文路径：方程里还缺一块——**$f_r$ 怎么取**（§4）；有了 $f_r$，再落到 Metal/Rough 贴图与直接光着色（§5）。工程上各阶 $L^{(k)}$ 的近似方式见上表；Cook-Torrance 伪代码算的是给定一盏灯时的 **$L^{(1)}$ 贡献**。





## 4. 填入 $f_r$：BRDF

渲染方程每一跳都是：

$$
\text{出射贡献} \;\propto\; f_r(\omega_i,\omega_o)\cdot L_i\cdot(\mathbf{n}\cdot\omega_i)
$$

§3 展开了 $L_i$（直接 / 各阶间接），**$f_r$ 描述「这一跳表面怎么反射」**——与来光是灯还是别的表面无关。PBR 把 $f_r$ 写成漫反射 + 镜面，镜面用 Cook-Torrance（DFG），再用能量守恒定 $k_d,k_s$。

$$
f_r = k_d\, f_{\text{lambert}} + k_s\, f_{\text{cook-torrance}},
\quad
f_{\text{lambert}} = \frac{c}{\pi}
$$

$c$ 为 albedo；$\pi$ 保证半球积分与能量一致。

镜面项（微平面）：
$$
f_{\text{cook-torrance}} = \frac{D(\mathbf{h})\,F(\omega_o,\mathbf{h})\,G(\omega_i,\omega_o,\mathbf{h})}{4\,(\mathbf{n}\cdot\omega_i)\,(\mathbf{n}\cdot\omega_o)},
\quad
\mathbf{h}=\frac{\omega_i+\omega_o}{\|\omega_i+\omega_o\|}
$$

相对 Blinn-Phong 的 $\cos^n(\mathbf{N}\cdot\mathbf{H})$，这里把「分布 / 菲涅尔 / 遮挡」拆开，并服从能量关系。

| 项 | 作用 | 常用形式 |
|:---|:---|:---|
| **D** | 微平面法线对齐 $\mathbf{h}$ 的程度 → 高光锐利度 | GGX：$\displaystyle D=\frac{\alpha^2}{\pi\bigl((\mathbf{n}\cdot\mathbf{h})^2(\alpha^2-1)+1\bigr)^2}$，$\alpha=\text{roughness}^2$ |
| **F** | 反射率随入射角变化（掠射更亮） | Schlick：$F=F_0+(1-F_0)(1-\cos\theta)^5$ |
| **G** | 微平面自遮挡 | Smith-GGX：$G=G_1(\omega_o)G_1(\omega_i)$，$G_1(\mathbf{v})=\frac{\mathbf{n}\cdot\mathbf{v}}{(\mathbf{n}\cdot\mathbf{v})(1-k)+k}$，$k=\frac{(\alpha+1)^2}{8}$ |

$F_0$：非金属约 $0.04$；金属取自 albedo。Metal/Rough 用 `lerp(0.04, albedo, metallic)`；Spec/Gloss 则直接用 Specular 贴图。粗糙 ↑ → D 变散、G 遮挡加重；掠射角上 $F$ 上升通常仍压过 $G$ 的下降，边缘往往更亮。





## 附录

### 1. 色彩空间：PBR 必须在线性空间中计算

渲染方程与 BRDF 都建立在**辐射率可加、可乘**的假设上，因此光照积分、能量守恒、$L_i\cdot f_r\cdot(\mathbf{n}\cdot\omega_i)$ 等运算都只能在**线性光空间（linear radiometric space）**中进行。显示器与多数色贴图使用的 sRGB / Gamma 编码是**非线性**的：若在编码空间里直接做加法或乘法，高光会偏暗、叠加会发灰，能量关系也不再成立。

工程上的正确流水线可以概括为：

```
sRGB 色贴图 / 输出缓冲
        │
        ▼  decode（常称 degamma / sRGB→Linear）
   线性空间（HDR）
        │  ← 光照、BRDF、IBL、合成全在这里
        ▼  tone mapping（可选，HDR→显示范围）
   近似 [0,1] 线性显示值
        ▼  encode（gamma / Linear→sRGB）
   送给显示器的帧缓冲
```

要点：

| 阶段 | 做什么 | 注意 |
|:---|:---|:---|
| **输入解码** | Albedo、Emissive 等**颜色**贴图从 sRGB 解到线性 | Normal / Roughness / Metallic / AO 等**数据**贴图本身应按线性存、线性读，不要做 sRGB 解码 |
| **着色** | 全部 PBR 与光累加在线性空间（通常 HDR） | 灯光强度、环境贴图采样结果也应是线性辐射量 |
| **色调映射** | 把 HDR 压到可显示范围 | 发生在线性（或专用 tone-map 曲线）空间，**不是**用 gamma 代替 tone map |
| **输出编码** | Linear → sRGB（或 $\gamma\approx 2.2$）再写入交换链 | 若交换链已是 `SRGB8`，硬件会在写入时编码，着色器里就不要再手动 gamma 一次 |

因此常见口诀「先 degamma → 线性里算光 → 再 gamma」**方向是对的**，但更准确的说法是：

> **色贴图与最终显示用 sRGB/Gamma 编码；进入着色前解码到线性，在线性空间完成全部光照，经 tone mapping 后再编码回显示空间。**

「在相机里做 degamma」容易误解：解码发生在**材质/纹理采样进入着色器之时**，而不是相机矩阵或镜头模型本身；后处理相机栈里常见的是 exposure、tone map 与最终 encode，而不是替代贴图解码。

粗略近似（仅示意，生产中优先用硬件 sRGB 采样器 / 标准 EOTF）：

$$
c_{\text{linear}} \approx c_{\text{sRGB}}^{\,2.2},\qquad
c_{\text{sRGB}} \approx c_{\text{linear}}^{\,1/2.2}
$$

真实 sRGB 在暗部有一段线性区，不完全等于纯幂次；引擎里应走 API 提供的 sRGB 格式，而不是随手 `pow`。

### 2. MatCap — PBR 的廉价替代


当完整 PBR + IBL 成本过高（移动端、海量实例、强风格化）时，可用 MatCap 近似「某种固定光照下的材质外观」。

### 基本原理

> **把一张球体的光照渲染结果当作贴图查表。**

1. 离线用完整 PBR + 环境光渲染球体正面
2. 存为 MatCap 贴图
3. 运行时用法线映射 UV，一次采样出颜色

```
u = Nx * 0.5 + 0.5
v = Ny * 0.5 + 0.5
// 忽略 Nz：法线压到球面正面投影
```

### Shader

```glsl
varying vec2 matcapCoord;
void main() {
    vec3 normal = normalize(mat3(modelViewMatrix) * aNormal);
    matcapCoord = normal.xy * 0.5 + 0.5;
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}

uniform sampler2D uMatCap;
varying vec2 matcapCoord;
void main() {
    gl_FragColor = texture2D(uMatCap, matcapCoord);
}
```

**整段着色几乎只有一次纹理采样，无实时 BRDF 积分。**

### 为何有效

$$\text{color}(N_x, N_y) = \underbrace{\text{PBR}(N, \text{envmap}, \text{material})}_{\text{离线预计算}}$$

| 完整 PBR | MatCap |
|:---|:---|
| 运行时积分 / 采样 IBL | 预结果查表 |
| 需环境光信息 | 烘焙进贴图 |
| 逐像素 DFG | 一次 `texture2D` |
| 视角变化仍物理正确 | **强依赖近似视角** |

### 生成方式

**离线**：Blender 等中对球体赋目标材质，HDRI + 正交正面渲染。  
**运行时**：把球体 PBR 结果渲染到 FBO，拷成纹理。

### 典型用途与限制

| MatCap 类型 | 适用 |
|:---|:---|
| 陶瓷 / 金属拉丝 / 布料 / 卡通 / 皮肤近似 | 风格化角色、手办感、固定机位场景 |

| 问题 | 缓解 |
|:---|:---|
| 视角依赖，「材质跟着转」 | 固定机位或限制使用范围 |
| 无自阴影 / 难跟动态光 | 叠 AO，或混少量实时光 |
| 分辨率导致细节不足 | Detail map |

### 性能位置

```
真实感 ──────────────────────> 开销

Unlit < MatCap < Diffuse+EnvMap < Simplified PBR < Full PBR < Ray Tracing
```

MatCap 夹在 Unlit 与简化 PBR 之间：用极低成本换远超纯色的观感。许多手游角色渲染会在不同程度上使用 MatCap 或其变体。
