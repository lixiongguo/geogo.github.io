# NeRF：Instant-NGP 加速

> Thomas Müller et al., *Instant Neural Graphics Primitives with a Multiresolution Hash Encoding*, SIGGRAPH 2022.  
> 索引：[Nerf.md](Nerf.md) · 前置：[Nerf_三大组成部分.md](Nerf_三大组成部分.md)

## 1. 原始 NeRF 为什么慢

每条射线几十～上百个采样点，每点一次大 MLP 前向；一张图百万像素 → 上亿次网络计算。瓶颈主要是：

1. **表达全靠 MLP 权重**，网络必须又深又宽；  
2. **空空间**仍在傻查；  
3. 训练框架（纯 PyTorch）内核不够贴体渲染访存模式。

Instant-NGP 的回答：把大部分空间变化塞进**可学习的多分辨率哈希表**，MLP 缩成「小解码器」，再加 CUDA 级优化。

## 2. 多分辨率哈希编码

### 2.1 结构

对输入坐标 $\mathbf{x}$（归一化到场景盒内）：

1. 在 $L$ 个分辨率层级上，找到覆盖 $\mathbf{x}$ 的体素；  
2. 每个体素角点通过 **空间哈希** 映到长度为 $T$ 的表项（存可学习特征向量）；  
3. 三线性（或更高维）插值得到该层特征；  
4. 拼接各层特征 → 送入 **tiny MLP**（往往 2～3 层、宽几十）→ $(c,\sigma)$ 或 SDF 等。

粗层捕获大结构，细层捕获细节；哈希冲突用学习消化（冲突特征被优化成「够用」的折中）。

### 2.2 和位置编码的对比

| | NeRF PE + 大 MLP | Instant-NGP |
|:---|:---|:---|
| 高频从哪来 | 傅里叶基 + 网络拟合 | 细网格特征直接存 |
| 参数落点 | 几乎全在权重 | 大头在哈希表 |
| 局部更新 | 改一处可能牵动全局 | 更偏局部体素 |

## 3. 工程加速要点

论文 / 官方实现不仅是换编码，还包括：

- **占用网格（occupancy grid）**：粗分辨率标记空体素，射线行进跳过空气；  
- **全 CUDA 训练**：采样、编码、MLP、体积积分、反传一条龙，减少 GPU↔框架开销；  
- 动态更新占用与学习率等训练技巧。

结果：许多场景 **秒～分钟级** 收敛到可交互预览，相对原版 NeRF 小时～天级是数量级变化。

## 4. 质量与代价

- **优点**：快、易交互调参、可接相机优化（iNGP 也常联合 refine 位姿）；  
- **注意**：哈希表大小、分辨率层数影响显存与细节；过拟合噪声、背景「烟」仍可能出现；无界场景需额外收缩 / 分前景背景（常与 Mip-NeRF 360 思想结合）。  
- **生态**：nerfstudio、NVIDIA instant-ngp 仓库、许多实时 NeRF 变体都以该编码为默认骨干。

## 5. 和 Plenoxels 的对照

| | Instant-NGP | Plenoxels |
|:---|:---|:---|
| 表示 | 哈希特征 + 小 MLP | 稀疏体素 + SH，无大网 |
| 外观 | MLP 解码，更灵活 | SH 系数，偏经典 |
| 共同点 | 显式空间结构 + 体渲染监督 | 同左 |

两者都说明：**慢不是体渲染公式的宿命，而是「大网逐点查」的实现选择。**

## 6. 一句话

**Instant-NGP = 多分辨率哈希网格扛空间细节 + 极小 MLP 解码 + 占用跳空 + CUDA——把 NeRF 从科研原型推进到可交互训练。**
