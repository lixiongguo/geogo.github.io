### **0.多实践才能会用**

Git的概念比较抽象，另外操作命令也不没有很直观，需要多实践中不断熟悉这个过程，本次分享仅是作为基本的介绍，

### **1.Git是什么？**

分布式版本管理工具

**1.0 版本管理工具是什么**

对于需要多人协作，长期修改更新的项目来说，版本管理必不可少。

用Word写长篇大论，想修改一个段落，又怕将来想恢复找不回来怎么办？有办法，先把当前文件备份为一个新的文件，再接着改，改到一定程度，再备份，这样一直改下去，最后就会有很多的文件难以管理：

![lots-of-docs](..\..\imgs\docs.jpg)

如果有其他人一起协作那这样的话版本会越来越多，靠个人记忆和手写记录就不可行了。所以希望有一个能自动帮你记录下修改内容的工具。

![image-20250422101539282](..\..\imgs\image-20250422101539282.png)

1.1 **中心与分布**

高效的分布式版本管理工具，区别于SVN的中心化版本管理工具

中心化版本管理工具是将版本库存放在中心服务器上的,中心化的SVN的优点是简单直接

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/e68ffa1937484a9bbc51ecea0f5ab863.png#pic_center)

分布式版本控制系统没有“中央服务器”，每个人的电脑上都是一个完整的版本库。

![img](https://i-blog.csdnimg.cn/direct/97c0f15769a34e6b892fba7b2aae509c.png#pic_center)

Git的主要优点是**极其强大的分支管理**，建立分支几乎0成本（SVN每次建立分支，合并分支等都对应着大量的文件操作，而对于git来说只是简单的移动了一下指针）

1.2 **历史与背景**

- git是由Linux发明人Linus开发的，世界上几乎所有大型的开源项目Linux，AOSP(Android)等都是用Git进行托管的
- GitHub是基于git开发的全球最大开源代码托管网站（国内访问并不稳定），Gitee是国内的对等产品。另外针对企业级方案也有GitLab等，企业可以部署到自己的服务器上。

### **3.提交(Commit)/上传(Push)/下载(Pull) 文件**

**3.1 工作区/版本库的介绍与提交文件**

![image-20250422110224795](..\..\imgs\image-20250422110224795.png)

工作区（Working Directory）
就是你在电脑里能看到的目录，包含了所有的项目文件，在工作区中进行文件的编辑、创建和删除等操作。

版本库（Repository）

工作区有一个隐藏目录`.git`，这个不算工作区，而是Git的版本库。Git的版本库里存了很多东西，其中最重要的就是称为stage（或者叫index）的暂存区

![image-20250422110729547](..\..\imgs\image-20250422110729547.png)

git的提交分两步

第一步是用`git add`把文件添加进去，实际上就是把文件修改添加到暂存区；

第二步是用`git commit`提交更改，实际上就是把暂存区的所有内容提交到当前分支

![image-20250422110353103](..\..\imgs\image-20250422110353103.png)

### **4.分支管理**

灵活高效的分支管理是git最核心的优点（git的操作远没有svn来的简单直观）

**4.1本地分支与远端分支的关联**

git checkout 指令切换与新建分支

```bash
$ git checkout -b devleop
```

git branch 显示当前分支

```bash
$ git branch -a
```

![image-20250422112547835](..\..\imgs\image-20250422112547835.png)

经过修改文件和提交文件后，需要上传(push)修改到远端develop分支，需要先建立关联

```bash
$ git push --set-upstream origin devleop
```

**实操：**在develop分支下新建test_dev.txt文件并提交上传

![image-20250422114852169](..\..\imgs\image-20250422114852169.png)



一般push到远端之前会要求本地与远端的代码是同步的(否则版本就乱了)，需要先用git pull命令进行同步，如果不同的分支修改了同一个地方的话那样就会有冲突，合理解决冲突是git的难点，如果没有妥善解决的话就会代码混乱(覆盖了别人的代码)

另外也可以用git branch命令来进行关联

```bash
git branch --set-upstream-to=<远程仓库名>/<远程分支名> <本地分支名>
```

**4.3 版本回退**

代码开发过程中不可避免的引入bug，解决bug一方面通过debug从代码上找出问题，另外一种方法是回退到之前测试充分的安全的版本。

**查看提交历史**

git log查看本分支的提交历史

![image-20250422122836922](..\..\imgs\image-20250422122836922.png)

git reflog查看所有分支的操作历史(更加紧凑)

![image-20250422122855208](..\..\imgs\image-20250422122855208.png)

可以看到每一个提交都会生成一个**commit hash**，这个是作为本次提交的唯一id，也是回退版本的标识

利用git reset回退到指定版本

git reset命令总共有三个模式 --hard --mixed(默认) --soft

![img](..\..\imgs\v2-8232f29a8c165e2e495688d60401f267_r.jpg)

--hard 清空工作目录，清空暂存区，当前的工作会丢失

--mixed (默认 ) :保留工作目录，清空暂存区,所以git add后可以通过此命令将暂存的内容撤销掉

 --soft：保留工作目录，保留暂存区，并会把因为保留工作目录内容所带来的新的文件差异放进暂存区。

**实操：**回退到没合并前的版本(“master 1”的那次提交）

![image-20250422123617622](..\..\imgs\image-20250422123617622.png)

HEAD代表此分支下的当前的提交指针，HEAD^代表上一个提交指针， HEAD^^代表上上次提交指针，同理以此类推....

**4.4 其他命令**

1.git stash 

暂存当前工作区内容（当前分支的内容改到一半，需要切到其他分支修改其他内容临时保存），与git reset --hard区别：stash只是暂时将工作区内容保存起来之后可以通过git stash pop还原回来，而git reset --hard当前工作区的内容就丢弃了

2.git cherry-pick

将代码从一个分支转移到另一个分支，需要另一个分支的所有代码变动那么就采用合并

需要部分代码变动（某几个提交），这时可以采用 Cherry pick

```bash
$ git cherry-pick <commitHash>
```
