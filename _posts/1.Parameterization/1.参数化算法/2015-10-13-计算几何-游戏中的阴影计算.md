## 朴素三角法

**基本思想**：从光源向物体顶点连线并延伸到接收面（地面/墙面等），形成阴影多边形。

### 算法流程

1. **构造阴影体 (Shadow Volume)**：对物体的每条轮廓边（silhouette edge），以光源为顶点、该边为底边，构建一个四边形/三角形"拉伸"到无穷远或接收面上
2. **模板缓冲 (Stencil Buffer)**：利用 Z-pass 或 Z-fail 算法标记屏幕上哪些像素处于阴影体内
3. **最终绘制**：根据 Stencil 值决定是否对像素进行光照

### 核心公式

给定光源位置 $\vec{L}$ 和顶点 $\vec{v}$，其在远平面上的投影点：

$$\vec{v}' = \vec{L} + \frac{\|\vec{f}_{far} - \vec{L}\|}{\|\vec{v} - \vec{L}\|} (\vec{v} - \vec{L})$$

其中 $\vec{f}_{far}$ 为视锥体远平面上某参考点。

### 优缺点

- **优点**：精确的逐像素阴影，无分辨率依赖
- **缺点**：
  - 需要找到正确的轮廓边 → 对复杂模型开销大
  - 模板缓冲操作填充率压力大
  - 与延迟渲染管线兼容性差
  - 无法处理半透明阴影和软阴影

> **适用场景**：早期固定功能管线时代；如今在特定需求下仍可用于小规模场景的精确硬阴影。

## Projector（投影纹理阴影）

**核心思路**：将一张预制的阴影纹理（shadow texture / cookie）通过一个投影矩阵"投射"到场景表面。

### 实现原理

1. **创建 Projector 矩阵**：将光源视为一个"摄像机"，构建其 view-projection 矩阵 $M_{proj}$：

$$M_{proj} = M_{projection}^{light} \cdot M_{view}^{light}$$

2. **生成投影坐标**：对于世界空间中的点 $\vec{p}_{world}$，其投影纹理坐标：

$$\vec{p}_{tex} = M_{proj} \cdot \vec{p}_{world}, \quad \text{然后做齐次除法和 [0,1] 映射}$$

3. **Shader 中采样**：

```hlsl
// Vertex Shader: 计算投影坐标
float4 posLightSpace = mul(unity_WorldToLight, float4(worldPos, 1.0));
o.projCoord = posLightSpace.xyzw / posLightSpace.w;

// Fragment Shader: 采样 shadow cookie
fixed4 texCookie = tex2Dproj(_LightTexture0, i.projCoord);
float atten = texCookie.a; // alpha 通道作为衰减/遮罩
```

### 典型应用

- **聚光灯 Cookie**：模拟百叶窗、树影等图案化光照效果
- **定向光阴影**：大面积区域使用低分辨率投影纹理作为近似阴影
- **性能优势**：仅需一次纹理采样，GPU 开销极低

### 局限性

- 阴影是**静态预制**的——无法随物体移动而实时更新
- 本质上是**伪阴影**：不能反映真实的几何遮挡关系
- 投影范围有限，适合局部区域

## Shadow Map（阴影贴图）

**当前实时渲染中最主流的阴影技术**。

### 基本原理

**两遍渲染 (Two-Pass Rendering)**：

1. **Shadow Pass（深度预渲染）**：
   - 从光源位置渲染整个场景，只输出深度值到一张深度纹理（Shadow Map）
   - 存储的是：**每个像素对应的空间点到光源的距离**

2. **Lighting Pass（着色阶段）**：
   - 从相机视角正常渲染场景
   - 将每个片段变换到光源空间，查询 Shadow Map 中的深度
   - 比较：若 $d_{fragment} > d_{map}$，则该片段处于阴影中

```glsl
// Shadow comparison in fragment shader
float shadow = 0.0;
vec3 projCoords = fs_in.FragPosLightSpace.xyz / fs_in.FragPosLightSpace.w;
projCoords = projCoords * 0.5 + 0.5; // [-1,1] -> [0,1]
float currentDepth = projCoords.z;
float closestDepth = texture(shadowMap, projCoords.xy).r;
shadow = currentDepth > closestDepth ? 1.0 : 0.0;
```

### 关键问题与解决方案

#### 1. Shadow Acne（阴影痤疮）

由于浮点精度限制，$d_{fragment}$ 与 $d_{map}$ 在接近时会交替判定，产生条纹状伪影。

**解决方法 — Bias（偏移量）**：
$$\text{shadow} = (d_{current} - \text{bias}) > d_{closest}$$

Bias 的选取需权衡：太小仍有 acne，太大则产生 **Peter Panning**（悬浮感）。

#### 2. Aliasing（锯齿/走样）

**原因**：Shadow Map 分辨率有限，远处阴影边缘出现锯齿。

**解决策略**：
- **PCF (Percentage Closer Filtering)**：对周围 $N \times N$ 个纹素做深度比较后取平均
  $$\text{shadow} = \frac{1}{N^2}\sum_{i=1}^{N^2} \text{compare}(d_{current}, d_i)$$
  - PCF $3\times3$ 是最常用的基础软阴影方案
- **PCSS (Percentage Closer Soft Shadows)**：根据遮挡物距离动态调整滤波核大小，模拟真实半影（penumbra）效果
- **VSM (Variance Shadow Maps)**：存储深度的均值和方差，允许用 GPU 双线性滤波直接实现软阴影
- **ESM (Exponential Shadow Maps)**：存储 $e^{-cd}$ 形式，将比较转为乘法，天然支持滤波

#### 3. Light Space Perspective Aliasing（透视锯齿）

**问题**：透视投影下近处阴影精度高、远处极差。

**解决方法 — CSM（级联阴影贴图）**和 **PSM（透视阴影贴图）**，详见后文。

### Shadow Map 变体总结

| 方法 | 存储内容 | 软阴影 | 抗锯齿能力 | 实现复杂度 |
|:-----|:---------|:-------|:-----------|:-----------|
| Standard SM | Depth only | 否 (仅 PCF 近似) | 低 | ⭐ |
| PCF SM | Depth only | 近似 (固定核) | 中 | ⭐⭐ |
| PCSS SM | Depth only | ✅ 物理正确 | 高 | ⭐⭐⭐ |
| VSM | $(d, d^2)$ | ✅ | 高 | ⭐⭐ |
| ESM | $e^{-cd}$ | ✅ | 高 | ⭐⭐ |
| MSM (Moment SM) | 多阶矩 | ✅ 更精确 | 很高 | ⭐⭐⭐⭐ |

## SDF Shadow（有向距离场阴影）

利用 **Signed Distance Field (SDF)** 进行实时光线步进（Ray Marching）来计算阴影。

### SDF 基础回顾

SDF 定义了一个标量场，任意点 $\vec{p}$ 到表面 $S$ 的**带符号最近距离**：

$$\phi(\vec{p}) = \begin{cases} +d(\vec{p}, S) & \vec{p} \text{ 在外部} \\ 0 & \vec{p} \in S \\ -d(\vec{p}, S) & \vec{p} \text{ 在内部} \end{cases}$$

### 光线步进求交

```glsl
// Ray marcher for shadow
float softShadow(vec3 ro, vec3 rd, float mint, float maxt, float k) {
    float res = 1.0;
    float t = mint;
    for (int i = 0; i < 64; i++) {
        float h = mapScene(ro + rd * t); // SDF 场求值
        if (h < 0.001) return 0.0;       // 击中物体 → 全暗
        res = min(res, k * h / t);        // 软阴影累积
        t += h;                           // 步进距离 = 当前 SDF 值
        if (t >= maxt) break;
    }
    return clamp(res, 0.0, 1.0);
}
```

### 软阴影原理

上述算法的关键在于 `res = min(k * h / t)` 这一行：

- 当光线**靠近**障碍物时（$h$ 小），且已经**走了较远的距离**（$t$ 大）→ $h/t$ 小 → 阴影深
- 参数 $k$ 控制**半影半径**（penumbra width）：越大则半影越窄

这就是著名的 **Soft Shadow by IQ (Inigo Quilez)** 算法，广泛用于 ShaderToy / demo scene 社区。

### 应用形式

| 形式 | 说明 | 适用场景 |
|:-----|:-----|:---------|
| **Screen-space SDF** | 从 depth buffer 重建 SDF | 后处理效果、SSAO 扩展 |
| **Volume Texture SDF** | 预计算烘焙到 3D 纹理 | Unity/UE4 的 Global Illumination |
| **Procedural SDF** | 用数学函数组合定义形状 | 程序化地形、体素渲染 |
| **SDF Font** | 字形用 SDF 表示 | UI 文字高质量阴影 |

### 优缺点

- **优点**：
  - 天然支持**高质量的软阴影**（含半影过渡）
  - 可同时实现环境光遮蔽 (AO)、反射、折射等多种效果
  - 对复杂几何体（如文字、程序化形状）非常高效
- **缺点**：
  - 需要 SDF 数据（预计算或过程式生成）
  - 光线步进迭代次数影响性能和质量
  - 动态场景需要更新 SDF → 开销大
  - 大尺度场景内存占用高

## CSM / PSM

两者都是为了解决 **Shadow Map 在透视投影下的精度分布不均** 问题，但思路截然不同。

### CSM — Cascaded Shadow Maps（级联阴影贴图）

**核心思想**：将视锥体沿深度方向切分成多个子级联（cascade），每个级联使用一张独立的高分辨率 Shadow Map。

#### 工作流程

```
视锥体划分示意:
┌─────────────────────────────┐
│  Cascade 0 (Near)           │  ← 最高分辨率 (如 2048×2048)
│  ┌───────────────────┐      │
│  │  Cascade 1         │      │  ← 中等分辨率 (如 1024²)
│  │  ┌─────────────┐   │      │
│  │  │ Cascade 2   │   │      │  ← 较低分辨率 (如 512²)
│  │  │ Cascade 3   │   │      │  ← 最低分辨率 (如 256²)
│  │  └─────────────┘   │      │
│  └───────────────────┘      │
└─────────────────────────────┘
```

1. **级联分割**：常用 **Practical Split Scheme**（对数 + 均匀混合）确定各 cascade 的近平面和远平面：

$$C_i = \lambda \cdot C_i^{log} + (1-\lambda) \cdot C_i^{uni}, \quad \lambda \in [0, 1]$$

   其中 $C_i^{log}$ 为对数分割点，$C_i^{uni}$ 为均匀分割点。

2. **选择级联**：渲染时根据片元到相机的深度 $z_{view}$ 选择对应的级联索引

3. **级联间过渡**：相邻级联边界处进行混合（blend），避免明显跳变

```hlsl
// 级联选择与混合 (简化版)
float CalculateCascadeBlend(float z_view) {
    float4 cascadeSplits = float4(10.0, 50.0, 150.0, 500.0);
    float4 inCascade = step(cascadeSplits, z_view.xxxx);
    int cascadeIndex = dot(inCascade, float4(3, 2, 1, 0));
    return cascadeIndex;
}
```

#### 优点

- **实用可靠**：几乎所有现代引擎的标准方案（Unity URP、Unreal Engine、id Tech 等）
- 近处高精度、远处适当降低 → 符合人眼感知特性
- 各级联可并行计算，易于 GPU 实现

#### 缺点

- 多张 Shadow Map → 显存开销增大（通常 4 张 2048² ≈ 64 MB）
- 级联边界处可能出现质量跳变（需额外平滑处理）
- 方向光效果最好；点光源需配合 Cube Map / Dual Paraboloid

### PSM — Perspective Shadow Maps（透视阴影贴图）

**核心思想**：在光源空间中对场景施加**透视变换**，使得近处的 Shadow Map 精度自动提高。

#### 数学原理

1. **后透视变换 (Post-perspective Transform)**：
   - 构建一个透视矩阵 $P_{psm}$，其焦点位于光源位置
   - 将所有顶点通过 $P_{psm}$ 变换后再生成 Shadow Map
   - 效果：**近处物体在 Shadow Map 中占据更多纹素**

2. **关键矩阵**：
$$P_{psm} = \begin{bmatrix} n & 0 & 0 & 0 \\ 0 & n & 0 & 0 \\ 0 & 0 & n+f & -nf \\ 0 & 1 & 0 & 0 \end{bmatrix}$$

（注意最后一行与标准透视矩阵不同——这是为了将透视除法应用到光源空间）

#### 致命问题

| 问题 | 描述 |
|:-----|:-----|
| **透视失真** | 经过透视变换后，某些物体会被扭曲到无穷远，导致 Shadow Map 覆盖失败 |
| **退化情况** | 当视线方向与光照方向接近平行时，PSM 会严重退化甚至完全失效 |
| **实现复杂度** | 需要特殊处理裁剪、反向映射等问题 |

#### 改进变体

- **LiSPSM (Light-Space Perspective Shadow Maps)**：在光源空间中应用透视变换，但避免了 PSM 的极端失真问题
- **TSM (Trajectory Shadow Maps)**：通过优化参数化的轨迹来改善精度分配

#### 现状

PSM 及其改进版在学术界有一定影响力，但**工业界几乎全部采用 CSM**。原因是：

1. CSM 更直观，参数调节更容易
2. PSM/LiSPSM 的 edge case 处理繁琐
3. 现代 GPU 显存已不是瓶颈，CSM 的显存开销完全可以接受

## 总结对比

| 技术 | 阴影类型 | 硬/软阴影 | 动态支持 | 性能开销 | 主流程度 |
|:-----|:---------|:----------|:---------|:---------|:---------|
| **朴素三角法 (Stencil Shadow Volume)** | 硬阴影 | 硬 | ✅ | 高（填充率瓶颈） | ❌ 已淘汰 |
| **Projector** | 伪阴影 | N/A | ❌ 静态 | 极低 | 局部使用 |
| **Shadow Map (+PCF/PCSS/VSM)** | 硬/软阴影 | PCF 近似 / PCSS 软 | ✅ | 中 | ✅✅ **绝对主流** |
| **SDF Ray Marching** | 软阴影 | ✅ 高质量 | 受限于 SDF 更新 | 中~高 | 特定领域 |
| **CSM** | SM 的精度增强方案 | 继承 SM | ✅ | 中（多张 map） | ✅✅ **行业标准** |
| **PSM / LiSPSM** | SM 的精度增强方案 | 继承 SM | ✅ | 中 | ⚠️ 学术价值 > 工业 |

> **实际工程建议**：绝大多数情况下直接使用 **CSM + PCSS (或 VSM/ESM)** 组合即可覆盖从移动端到高端 PC 的全部阴影需求。
