碰撞检测是游戏开发、物理模拟、机器人学中的核心问题。本文从粗检测到精检测，系统梳理碰撞检测算法体系。

## 1. 碰撞检测的分层架构

实际的碰撞检测系统通常分为**两个阶段**：

$$\underbrace{\text{Broad Phase（粗检测）}}_{\text{快速排除不可能碰撞的物体对}} \to \underbrace{\text{Narrow Phase（精检测）}}_{\text{精确判断是否碰撞 + 计算碰撞信息}}$$

| 阶段 | 目标 | 方法 | 复杂度（$n$ 个物体） |
|:---|:---|:---|:---|
| **Broad Phase** | 快速排除不可能碰撞的对 | AABB 粗检、空间划分、BVH | $O(n \log n)$ |
| **Narrow Phase** | 精确判断碰撞并计算碰撞信息 | SAT、GJK、EPA | $O(1)$ 每对 |

为什么需要分层？朴素方法需要 $O(n^2)$ 两两检测，当 $n = 10^4$ 时完全不现实。Broad Phase 将候选对从 $O(n^2)$ 降到 $O(n \log n)$，Narrow Phase 对每对候选做精确检测。

## 2. 包围体（Bounding Volume）——Broad Phase 的基础

### 2.1 包围球（Bounding Sphere）

最简单的包围体，用球心 $c$ 和半径 $r$ 表示。

**碰撞判断**：两球心距离 < 半径之和

$$\|c_A - c_B\|^2 < (r_A + r_B)^2$$

注意：比较**距离的平方**以避免开方运算。

| 优点 | 缺点 |
|:---|:---|
| 计算极快，$O(1)$ | 对长条形物体包裹不紧 |
| 旋转不变（球旋转后不变） | 大量误报（false positive） |
| 容易计算（取最远顶点对） | 无法利用物体方向信息 |

### 2.2 AABB（Axis-Aligned Bounding Box）

轴对齐包围盒：边平行于坐标轴的长方体。用 $(x_{\min}, x_{\max}, y_{\min}, y_{\max})$ 表示。

**碰撞判断**：三个轴上投影都重叠

$$\text{AABB}_A \cap \text{AABB}_B \neq \emptyset \iff \begin{cases} x_{\min}^A \leq x_{\max}^B \text{ 且 } x_{\max}^A \geq x_{\min}^B \\ y_{\min}^A \leq y_{\max}^B \text{ 且 } y_{\max}^A \geq y_{\min}^B \\ z_{\min}^A \leq z_{\max}^B \text{ 且 } z_{\max}^A \geq z_{\min}^B \end{cases}$$

```c
bool AABBIntersect(AABB a, AABB b) {
    return (a.minX <= b.maxX && a.maxX >= b.minX) &&
           (a.minY <= b.maxY && a.maxY >= b.minY) &&
           (a.minZ <= b.maxZ && a.maxZ >= b.minZ);
}
```

| 优点 | 缺点 |
|:---|:---|
| 比包围球更紧凑（尤其对扁平/方形物体） | 不旋转不变——物体旋转后需重新计算 |
| 6 次比较即可判断 | 对倾斜的长条物体包裹仍不够紧 |
| 内存开销小（6 个浮点数） | — |

### 2.3 OBB（Oriented Bounding Box）

有向包围盒：允许旋转的 AABB。用中心 $c$、三个半轴向量 $\mathbf{u}, \mathbf{v}, \mathbf{w}$ 和三个半长度 $h_u, h_v, h_w$ 表示。

**碰撞判断**：需要 15 条分离轴（见 SAT 部分）。

| 优点 | 缺点 |
|:---|:---|
| 比 AABB 紧密得多（利用物体方向） | 碰撞检测更复杂（15 条分离轴） |
| 旋转后只需重新计算轴向，不需要重新拟合 | 包围体更新代价高 |

### 2.4 三种包围体对比

| 维度 | 包围球 | AABB | OBB |
|:---|:---|:---|:---|
| **紧凑度** | ★☆☆ | ★★☆ | ★★★ |
| **检测速度** | ★★★ | ★★★ | ★★☆ |
| **旋转适应** | ★★★（不变） | ★☆☆（需重构） | ★★★（随物体旋转） |
| **更新代价** | ★★★（不变） | ★★☆ | ★☆☆ |
| **内存** | 4 floats | 6 floats | 15 floats |

工程实践中最常见的组合：**Broad Phase 用 AABB，Narrow Phase 用 GJK**。

## 3. 空间划分——Broad Phase 加速

### 3.1 为什么需要空间划分

即使使用 AABB 粗检，$n$ 个物体仍需 $O(n^2)$ 次检测。空间划分的核心思想：

> 如果两个物体在空间上相距很远，它们的 AABB 一定不相交，无需检测。

### 3.2 BVH（Bounding Volume Hierarchy）

**BVH** 是一棵二叉树，每个节点存储一个包围体（通常是 AABB），叶子节点对应一个物体。

**构建**：自顶向下递归——选择最长的轴，按中位数切分，左右子树分别构建。

**查询**：从根节点开始，如果两棵 BVH 的根节点 AABB 不相交，则它们的子树都不可能相交，直接跳过。

```
function BVHIntersect(nodeA, nodeB):
    if NOT AABBIntersect(nodeA.box, nodeB.box):
        return false  // 剪枝！

    if nodeA.isLeaf AND nodeB.isLeaf:
        return NarrowPhase(nodeA.object, nodeB.object)

    // 递归展开较大（更多子节点）的节点
    if nodeA.area > nodeB.area:
        for each child of nodeA:
            if BVHIntersect(child, nodeB):
                return true
    else:
        for each child of nodeB:
            if BVHIntersect(nodeA, child):
                return true
    return false
```

**动态更新**：物体移动后，BVH 需要更新。常用策略：
- **Refit**：重新计算每个节点的 AABB（$O(n)$），不改变树结构
- **Rebuild**：当节点偏离过多时完全重建（通常每 N 帧一次）

### 3.3 其他空间划分方法

| 方法 | 数据结构 | 适用场景 |
|:---|:---|:---|
| **均匀网格（Uniform Grid）** | 3D 数组 | 物体均匀分布、大小相近 |
| **八叉树（Octree）** | 递归八分空间 | 大范围 3D 场景 |
| **四叉树（Quadtree）** | 递归四分 2D 空间 | 2D 游戏 |
| **KD 树** | 按轴交替切分 | 静态场景（射线追踪常用） |
| **Sort and Sweep** | 沿轴排序 + 扫描 | 动态物体较多的场景 |

## 4. SAT（分离轴定理）——Narrow Phase 基础

### 4.1 定理

**分离轴定理（Separating Axis Theorem, SAT）**：

> 两个**凸**多边形（或多面体）不相交，当且仅当存在一条**分离轴**，使得两个多边形在该轴上的投影不重叠。

等价表述：如果两个凸体在**所有候选分离轴**上的投影都重叠，则它们**相交**。

### 4.2 候选分离轴

| 形状 | 候选分离轴 | 轴的数量 |
|:---|:---|:---|
| **两个凸多边形** | 两条边的法线 | $n_A + n_B$ 条 |
| **两个 OBB** | 6 个面法线 + 9 个边叉积 | **15 条** |
| **两个 AABB** | 3 个坐标轴 | 3 条 |
| **OBB vs AABB** | 3 + 3 + 9 = | 15 条 |

### 4.3 SAT 算法流程

```
function SAT(A, B):
    axes = GetCandidateAxes(A, B)

    for each axis in axes:
        // 将两个物体投影到该轴上
        [minA, maxA] = Project(A, axis)
        [minB, maxB] = Project(B, axis)

        // 检查投影是否重叠
        if maxA < minB OR maxB < minA:
            return false  // 找到分离轴 → 不相交！

        // 记录最小重叠量（用于穿透深度）
        overlap = min(maxA, maxB) - max(minA, minB)
        if overlap < minOverlap:
            minOverlap = overlap
            collisionNormal = axis

    return true  // 所有轴都重叠 → 相交
```

### 4.4 投影计算

将多边形投影到轴 $\mathbf{n}$ 上：

$$\text{Project}(P, \mathbf{n}) = \left[\min_{v \in P}(v \cdot \mathbf{n}),\ \max_{v \in P}(v \cdot \mathbf{n})\right]$$

| 优点 | 缺点 |
|:---|:---|
| 概念直观，实现相对简单 | 只适用于**凸**体 |
| 天然提供穿透深度和碰撞法线 | 候选轴数量随形状复杂度线性增长 |
| 2D 多边形效果很好 | 3D 多面体可能有很多候选轴 |

## 5. GJK 算法——通用的凸体碰撞检测

### 5.1 核心思想

**GJK（Gilbert-Johnson-Keerthi, 1988）** 是一种通用的凸体碰撞检测算法，适用于**任何凸体**（不限于多边形），且不需要枚举所有分离轴。

其核心观察：

> **判断两个凸体 $A$ 和 $B$ 是否相交，等价于判断它们的闵可夫斯基差是否包含原点。**

### 5.2 闵可夫斯基差（Minkowski Difference）

$$A \ominus B = \{\mathbf{a} - \mathbf{b} \mid \mathbf{a} \in A,\ \mathbf{b} \in B\}$$

**关键定理**：

$$A \cap B \neq \emptyset \iff \mathbf{0} \in A \ominus B$$

即：$A$ 和 $B$ 相交当且仅当原点在闵可夫斯基差内。

**闵可夫斯基差的性质**：若 $A$ 和 $B$ 是凸体，则 $A \ominus B$ 也是凸体。

### 5.3 Support 函数

Support 函数返回凸体在给定方向上的**最远点**：

$$S_C(\mathbf{d}) = \arg\max_{\mathbf{c} \in C} (\mathbf{c} \cdot \mathbf{d})$$

**关键性质**：闵可夫斯基差的 Support 函数可以分解：

$$S_{A \ominus B}(\mathbf{d}) = S_A(\mathbf{d}) - S_B(-\mathbf{d})$$

这意味着我们**不需要显式计算闵可夫斯基差**（它可能有无穷多个点），只需要通过 Support 函数"采样"它。

**不同形状的 Support 函数**：

| 形状 | Support 函数 $S(\mathbf{d})$ |
|:---|:---|
| **球体**（中心 $\mathbf{c}$，半径 $r$） | $\mathbf{c} + r \cdot \hat{\mathbf{d}}$ |
| **AABB**（中心 $\mathbf{c}$，半尺寸 $\mathbf{h}$） | $\mathbf{c} + (h_x \text{sign}(d_x),\ h_y \text{sign}(d_y),\ h_z \text{sign}(d_z))$ |
| **凸多面体**（顶点集 $V$） | $\arg\max_{\mathbf{v} \in V} (\mathbf{v} \cdot \mathbf{d})$ |
| **胶囊体**（中心 $\mathbf{c}$，半高 $h$，半径 $r$） | $\mathbf{c} + h \cdot \text{sign}(\hat{\mathbf{d}}_y) \cdot \hat{\mathbf{y}} + r \cdot \text{proj}(\hat{\mathbf{d}}, \perp\hat{\mathbf{y}})$ |

### 5.4 Simplex

GJK 通过迭代构建一个**单纯形（Simplex）**来逼近原点：
- 2D 中：点 → 线段 → 三角形
- 3D 中：点 → 线段 → 三角形 → 四面体

每轮迭代，GJK 向原点方向搜索新的 Support 点，然后判断原点是否在当前 Simplex 内。如果不在，就缩减 Simplex（去掉最远的点），继续迭代。

### 5.5 GJK 完整伪代码

```
function GJK(Shape A, Shape B):
    d = B.center - A.center  // 初始方向：A 中心指向 B 中心
    simplex = []

    // 获取第一个 Support 点
    simplex.add(Support(A, B, d))
    d = -simplex[0]  // 反向：从第一个点指向原点

    for iteration = 1 to MAX_ITERATIONS:
        // 在当前方向上获取新的 Support 点
        A_new = Support(A, B, d)

        // 如果新点没有越过原点 → 原点不在闵可夫斯基差内
        if dot(A_new, d) < 0:
            return (false, 0)  // 不相交

        simplex.add(A_new)

        // 检查 Simplex 是否包含原点
        (contains, d) = SimplexContainsOrigin(simplex)
        if contains:
            return (true, simplex)  // 相交！返回 Simplex 给 EPA
        // 否则 d 已更新为新的搜索方向

    return (false, 0)  // 超过最大迭代次数

function Support(A, B, direction):
    return SupportA(A, direction) - SupportB(B, -direction)

function SimplexContainsOrigin(simplex):
    if simplex.size == 2:  // 线段
        return LineContainsOrigin(simplex)
    elif simplex.size == 3:  // 三角形（2D）/ 三角形（3D 中间态）
        return TriangleContainsOrigin(simplex)
    elif simplex.size == 4:  // 四面体（3D）
        return TetrahedronContainsOrigin(simplex)

function TriangleContainsOrigin(simplex):
    // simplex = [A, B, C]（逆时针）
    A = simplex[0], B = simplex[1], C = simplex[2]
    AB = B - A, AC = C - A, AO = -A

    // 检查原点是否在 AB 边的外侧
    if dot(AB, AO) > 0:
        simplex = [A, B]  // 缩减为 AB 线段
        return (false, cross(cross(AB, AO), AB))  // 垂直于 AB 指向原点

    // 检查原点是否在 AC 边的外侧
    if dot(AC, AO) > 0:
        simplex = [A, C]  // 缩减为 AC 线段
        return (false, cross(cross(AC, AO), AC))

    // 原点在三角形内部
    return (true, zero_vector)
```

### 5.6 GJK 的复杂度

| 维度 | 复杂度 |
|:---|:---|
| **每次迭代** | $O(V)$（$V$ 是凸体顶点数，用于计算 Support） |
| **迭代次数** | 通常 $< 64$（实践中极少超过 20） |
| **总复杂度** | $O(V)$（几乎常数时间） |

GJK 的收敛速度非常快，这就是为什么它是大多数物理引擎（Box2D, Bullet, PhysX, Jolt）的首选 Narrow Phase 算法。

## 6. EPA 算法——计算穿透深度

### 6.1 GJK 的局限

GJK 只能回答**是否碰撞**，但物理模拟还需要：
- **穿透深度（Penetration Depth）**：两个物体互相穿透了多少
- **碰撞法线（Collision Normal）**：沿什么方向将两个物体推开

**EPA（Expanding Polytope Algorithm）** 正是用来解决这个问题的。

### 6.2 EPA 的核心思想

GJK 检测到碰撞时，最终的 Simplex 是一个包含原点的三角形（2D）或四面体（3D）。EPA 从这个 Simplex 出发，**不断向原点方向扩展**，直到找到闵可夫斯基差表面上的最近点。

$$\text{穿透深度} = \| \mathbf{p} \|, \quad \text{碰撞法线} = \frac{\mathbf{p}}{\|\mathbf{p}\|}$$

其中 $\mathbf{p}$ 是闵可夫斯基差表面上离原点最近的点。

### 6.3 EPA 算法流程

```
function EPA(Shape A, Shape B, simplex_from_GJK):
    // 1. 从 GJK 的 Simplex 构建初始多面体
    polytope = BuildConvexPolytope(simplex_from_GJK)

    for iteration = 1 to MAX_ITERATIONS:
        // 2. 找到离原点最近的面
        face = FindClosestFace(polytope)
        normal = face.normal
        distance = face.distance_to_origin

        // 3. 在该法线方向获取新的 Support 点
        support = Support(A, B, normal)

        // 4. 检查新点是否超出当前最近面
        if dot(support, normal) - distance < EPA_TOLERANCE:
            return (normal, distance)  // 收敛！

        // 5. 将新点加入多面体，删除可见面，添加新的三角面
        polytope = ExpandPolytope(polytope, support, normal)

    return (normal, distance)  // 超时返回当前最优解
```

### 6.4 GJK + EPA 的组合

```
碰撞检测完整流程：
  1. Broad Phase (AABB / BVH) → 过滤不可能碰撞的对
  2. GJK → 判断是否碰撞（是/否）
  3. 如果碰撞 → EPA → 计算穿透深度和碰撞法线
  4. 碰撞响应（物理引擎）：根据穿透深度和法线进行位置修正/速度反弹
```

## 7. 算法对比总结

| 方法 | 适用形状 | 检测内容 | 复杂度 | 主要用途 |
|:---|:---|:---|:---|:---|
| **AABB** | 任意 | 粗检（是否可能碰撞） | $O(1)$ 每对 | Broad Phase |
| **OBB** | 任意 | 较精确粗检 | $O(1)$ 每对 | 动态物体的 Broad Phase |
| **BVH** | 任意 | 大规模场景加速 | $O(n \log n)$ | Broad Phase 加速 |
| **SAT** | 凸体 | 精确碰撞 + 穿透深度 | $O(n_A + n_B)$ 轴 | 简单凸体的 Narrow Phase |
| **GJK** | 凸体 | 精确碰撞判断 | $O(V)$ 迭代 | 通用 Narrow Phase |
| **EPA** | 凸体 | 穿透深度 + 法线 | $O(V)$ 迭代 | 碰撞响应输入 |

**工程推荐组合**：

$$\boxed{\text{AABB + BVH}} \xrightarrow{\text{Broad Phase}} \boxed{\text{GJK + EPA}} \xrightarrow{\text{Narrow Phase}} \boxed{\text{碰撞响应}}$$

这也是 Box2D（2D）和 Bullet/PhysX/Jolt（3D）等主流物理引擎所采用的架构。
