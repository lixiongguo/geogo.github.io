光线追踪（Ray Tracing）是计算机图形学中模拟光照的核心方法。本文从经典的 Whitted 递归光线追踪出发，逐步演进到基于物理的蒙特卡洛路径追踪，并讨论其加速策略。

<!--more-->

---

## 1. 为什么需要光线追踪

光栅化（Rasterization）擅长快速渲染几何体，但在处理以下全局光照效果时有本质困难：

- **软阴影**（Soft Shadows）：光源有面积时的半影效果
- **光泽反射**（Glossy Reflection）：非完美镜面的模糊反射
- **间接光照**（Indirect Illumination）：光线在物体间多次弹射后的效果
- **焦散**（Caustics）：光线通过透明体聚焦后形成的亮斑

光栅化只计算**直接光照**（眼睛 → 物体 → 光源，一次反射），无法处理光线的多次弹射。光线追踪通过**追踪光线的传播路径**来精确模拟这些效果。

> **核心假设**：
> - 光沿直线传播
> - 光线之间不会碰撞
> - 光线可逆（从相机出发和从光源出发等价）

## 2. Whitted 风格光线追踪

### 2.1 算法概览

Whitted（1979）提出了一种递归式光线追踪算法。它从相机出发，对每个像素发射一条光线，在交点处递归地生成反射、折射和阴影光线。

### 2.2 三种光线

| 光线类型 | 起点 | 方向 | 作用 |
|:---|:---|:---|:---|
| **主射线（Primary Ray）** | 相机 | 穿过像素平面进入场景 | 找到最近的交点 |
| **阴影射线（Shadow Ray）** | 交点 | 指向光源 | 判断交点是否在阴影中 |
| **反射/折射射线** | 交点 | 按反射/折射定律计算 | 模拟镜面反射和透明材质 |

### 2.3 反射与折射的数学

**反射方向**（入射角 = 反射角）：

$$\mathbf{R} = \mathbf{I} - 2(\mathbf{I} \cdot \mathbf{N})\mathbf{N}$$

其中 $\mathbf{I}$ 是入射方向（指向表面），$\mathbf{N}$ 是表面法线。

**折射方向**（Snell 定律）：

$$\frac{\sin\theta_1}{\sin\theta_2} = \frac{\eta_1}{\eta_2}$$

$$\mathbf{T} = \frac{\eta_1}{\eta_2}\mathbf{I} + \left(\frac{\eta_1}{\eta_2}\cos\theta_i - \cos\theta_t\right)\mathbf{N}$$

**菲涅耳项（Fresnel）**：决定反射和折射的比例：

$$F_R = F_0 + (1 - F_0)(1 - \cos\theta_i)^5$$

其中 $F_0$ 是垂直入射时的反射率。

### 2.4 完整伪代码

```
function WhittedRayTrace(scene, ray, depth):
    if depth <= 0:
        return backgroundColor

    // 1. 找最近交点
    hit = FindClosestIntersection(scene, ray)
    if no hit:
        return backgroundColor

    color = BLACK
    point = hit.point
    normal = hit.normal

    // 2. 直接光照（阴影射线）
    for each light in scene.lights:
        shadowDir = light.position - point
        shadowRay = Ray(point + epsilon * normal, shadowDir)

        if NOT IntersectsAnyObject(scene, shadowRay):
            // 不在阴影中，计算光照
            color += shading(hit.material, normal, light, shadowDir)

    // 3. 反射
    if hit.material.reflective AND depth > 0:
        reflectDir = Reflect(ray.direction, normal)
        reflectRay = Ray(point + epsilon * normal, reflectDir)
        reflectColor = WhittedRayTrace(scene, reflectRay, depth - 1)
        color += hit.material.reflectivity * reflectColor

    // 4. 折射
    if hit.material.transparent AND depth > 0:
        refractDir = Refract(ray.direction, normal, hit.material.ior)
        if refractDir exists:  // 非全反射
            refractRay = Ray(point - epsilon * normal, refractDir)
            refractColor = WhittedRayTrace(scene, refractRay, depth - 1)
            color += hit.material.transparency * refractColor

    return color
```

### 2.5 Whitted 光追的局限

Whitted 光追在每次交点只生成**确定性的**反射/折射光线，这导致它无法模拟以下效果：

- **漫反射的间接光照**：粗糙表面反射的光会照亮周围物体，但 Whitted 只处理镜面反射
- **软阴影**：只生成一条阴影光线，结果只有硬阴影
- **焦散**：光线通过透镜聚焦后的复杂效果
- **光泽反射**：只能做完美镜面或完全漫反射，没有中间状态

这些问题需要**路径追踪（Path Tracing）**来解决。

## 3. 路径追踪（Path Tracing）

### 3.1 渲染方程

路径追踪的理论基础是 Kajiya（1986）提出的**渲染方程**：

$$L_o(\mathbf{p}, \omega_o) = L_e(\mathbf{p}, \omega_o) + \int_{\Omega^+} f_r(\mathbf{p}, \omega_i, \omega_o) \cdot L_i(\mathbf{p}, \omega_i) \cdot (\mathbf{n} \cdot \omega_i) \, d\omega_i$$

各符号含义：

| 符号 | 含义 |
|:---|:---|
| $L_o(\mathbf{p}, \omega_o)$ | 点 $\mathbf{p}$ 沿方向 $\omega_o$ 的出射光亮度 |
| $L_e(\mathbf{p}, \omega_o)$ | 自发光（光源） |
| $f_r(\mathbf{p}, \omega_i, \omega_o)$ | BRDF（双向反射分布函数） |
| $L_i(\mathbf{p}, \omega_i)$ | 沿方向 $\omega_i$ 的入射光亮度 |
| $\mathbf{n} \cdot \omega_i$ | 余弦项（Lambert 定律） |

渲染方程本质上是一个**积分方程**——出射光 = 自发光 + 入射光在半球面上的加权积分。难点在于：这个积分通常没有解析解。

### 3.2 蒙特卡洛积分

既然无法直接计算渲染方程的积分，路径追踪使用**蒙特卡洛方法**来近似：

$$\int_a^b f(x) \, dx \approx \frac{1}{N} \sum_{i=1}^{N} \frac{f(x_i)}{p(x_i)}$$

其中 $x_i$ 是按概率密度 $p(x)$ 采样得到的随机点。

应用到渲染方程：

> 在半球面上随机采样一个方向 $\omega_i$，沿该方向发射一条光线，获得该方向的入射光亮度 $L_i$，再乘以 BRDF 和余弦项。重复多次取平均，即可逼近积分值。

### 3.3 路径追踪算法

```
function PathTrace(scene, ray, depth):
    if depth <= 0:
        return backgroundColor

    hit = FindClosestIntersection(scene, ray)
    if no hit:
        return backgroundColor

    // 自发光
    color = hit.material.emissive

    // 直接光照（光源采样 = 重要性采样）
    for each light in scene.lights:
        lightDir, lightDist = SampleLight(light)
        shadowRay = Ray(hit.point + epsilon * normal, lightDir)

        if NOT IntersectsAnyObject(scene, shadowRay, lightDist):
            // 计算直接光照贡献
            L_i = light.intensity / lightDist^2
            pdf = light.pdf
            color += hit.material.BRDF(normal, lightDir, -ray.direction)
                   * L_i * max(0, dot(normal, lightDir)) / pdf

    // 间接光照（随机采样半球方向）
    // 1. 在半球面上按余弦加权随机采样
    wi, pdf = CosineWeightedHemisphereSample(normal)

    // 2. 沿该方向发射光线（递归）
    indirectRay = Ray(hit.point + epsilon * normal, wi)
    L_i = PathTrace(scene, indirectRay, depth - 1)

    // 3. 计算 BRDF 贡献
    f_r = hit.material.BRDF(normal, wi, -ray.direction)
    cos_term = max(0, dot(normal, wi))
    color += f_r * L_i * cos_term / pdf

    return color
```

### 3.4 俄罗斯轮盘赌（Russian Roulette）

路径追踪的递归深度无法预先确定——理论上光线可以在场景中无限弹射。如果简单地设定一个最大深度，会导致深路径的贡献被截断，产生偏差。

**俄罗斯轮盘赌**（RR）提供了一种**无偏**的截断方法：

```
// 在每次递归前，以概率 P_RR 决定是否继续
P_RR = 0.8  // 存活概率

if random() > P_RR:
    return BLACK  // 终止路径

// 如果继续，贡献值除以 P_RR 以保持期望正确
indirect_color = PathTrace(...) / P_RR
```

**数学正确性**：设某条路径的真实贡献为 $C$。使用 RR 后：

$$E[\text{output}] = P_{RR} \cdot \frac{C}{P_{RR}} + (1 - P_{RR}) \cdot 0 = C$$

期望值不变，因此 RR 是**无偏的**——理论上，路径追踪的输出是渲染方程的**无偏估计**。

### 3.5 采样策略与降噪

路径追踪的核心问题是**噪声（noise）**——采样数不足时，蒙特卡洛积分的方差很大。

| 策略 | 方法 | 效果 |
|:---|:---|:---|
| **增加 SPP** | 每像素发射更多路径 | 降低方差，但线性增加计算量 |
| **重要性采样** | 偏向光源/BRDF 峰值方向采样 | 大幅降低方差 |
| **直接光照分离** | 显式采样光源计算直接光照 | 最高效的降噪手段 |
| **双向路径追踪（BDPT）** | 同时从相机和光源采样 | 处理困难光照路径 |
| **多重要性采样（MIS）** | 组合多个采样策略 | 进一步降低方差 |
| **后处理降噪** | 空间/时域滤波 | 最终图像平滑（可能引入模糊） |

### 3.6 Whitted vs 路径追踪

| 维度 | Whitted 光追 | 路径追踪 |
|:---|:---|:---|
| **间接光照** | ❌ 只处理镜面反射 | ✅ 蒙特卡洛积分处理所有反射 |
| **软阴影** | ❌ 硬阴影 | ✅ 面光源自然产生软阴影 |
| **物理正确** | ❌ 启发式模型 | ✅ 基于渲染方程 |
| **噪声** | 无 | 有（需多 SPP 降噪） |
| **速度** | 快（确定性光线） | 慢（随机采样） |
| **用途** | 实时渲染、游戏 | 离线渲染、电影 |

## 4. 路径追踪加速

路径追踪的计算瓶颈在于**射线-场景求交**——每条路径需要数十次射线求交，而一个场景可能有数百万个三角形。暴力遍历的复杂度为 $O(n)$ 每条射线，完全不实用。

### 4.1 BVH vs KD Tree

两种最常用的加速结构：

| 维度 | BVH（包围体层次） | KD Tree（KD 树） |
|:---|:---|:---|
| **划分对象** | 物体（三角形的包围盒） | 空间（轴对齐平面切分） |
| **构建速度** | 快（$O(n \log n)$） | 较慢（$O(n \log^2 n)$，SAH 优化） |
| **遍历效率** | 高（紧凑的包围盒） | 通常更快（更精确的空间划分） |
| **动态场景** | ✅ 易于更新（Refit） | ❌ 难以更新（需重建） |
| **内存开销** | 低 | 较高（需存储分割平面） |
| **GPU 适用性** | ✅ 适合 | ⚠️ 不太适合 |

**工程实践**：现代光线追踪器（如 RTX 光追、Embree）**几乎统一使用 BVH**，主要因为构建和更新更高效，对动态场景更友好。

### 4.2 SAH（Surface Area Heuristic）

**SAH（表面积启发式）** 是指导 BVH 构建的最优分割策略。其核心洞察：

> 一条随机射线击中某个包围盒的概率，与该包围盒的**表面积成正比**。

基于此，BVH 节点的射线遍历代价估计为：

$$C_{\text{split}} = C_{\text{trav}} + P_A \cdot N_A \cdot C_{\text{isect}} + P_B \cdot N_B \cdot C_{\text{isect}}$$

其中：
- $C_{\text{trav}}$：遍历一个节点的固定开销
- $C_{\text{isect}}$：一次射线-图元相交测试的开销
- $P_A = \frac{SA(A)}{SA(\text{parent})}$：射线击中左子树的概率（= 左子树表面积 / 父节点表面积）
- $N_A, N_B$：左右子树的图元数量

**构建时**：对每个候选分割平面计算上述代价，选择使 $C_{\text{split}}$ 最小的分割。

```
function BuildBVH_SAH(primitives):
    if |primitives| <= LEAF_SIZE:
        return LeafNode(primitives)

    best_cost = infinity
    best_axis, best_split = None

    for each axis in {x, y, z}:
        // 对图元按该轴排序
        sort primitives by centroid[axis]

        // 遍历所有可能的分割位置
        for split in candidates:
            left = primitives[:split]
            right = primitives[split:]

            cost = C_trav
                  + SA(left_bbox) / SA(parent_bbox) * |left| * C_isect
                  + SA(right_bbox) / SA(parent_bbox) * |right| * C_isect

            if cost < best_cost:
                best_cost = cost
                best_axis = axis
                best_split = split

    left_node = BuildBVH_SAH(primitives[:best_split])
    right_node = BuildBVH_SAH(primitives[best_split:])
    return InternalNode(left_node, right_node)
```

SAH 构建的 BVH 遍历效率远优于简单的中位数分割或等量划分，是现代光线追踪器的**标准构建策略**。

### 4.3 Morton Code 与 LBVH

**Morton Code（莫顿码）** 也称为 Z-order curve，是一种将 3D 坐标编码为一维整数的方法：

$$\text{Morton}(x, y, z) = \text{InterleaveBits}(x, y, z)$$

例如，$(5, 3, 6)$ 的 Morton 码通过将 $x, y, z$ 的二进制位交错得到：

```
x = 5 = 101
y = 3 = 011
z = 6 = 110

Morton = 100 111 010  (交错: z2y2x2 z1y1x1 z0y0x0)
       = 100111010
```

**关键性质**：3D 空间中**位置相近**的点，其 Morton 码也**相近**。这意味着按 Morton 码排序后，空间上相邻的三角形会被排在一起。

**LBVH（Linear BVH）** 利用这一性质：

```
function BuildLBVH(triangles):
    // 1. 计算每个三角形重心的 Morton 码
    for each tri in triangles:
        morton_code = MortonEncode(tri.centroid)
        tri.morton = morton_code

    // 2. 按 Morton 码排序（O(n log n)）
    sort triangles by morton_code

    // 3. 自顶向下按 Morton 码的最高有效位分割
    //    或使用并行前缀和构建（GPU 友好）
    return BuildTreeRecursive(triangles, 0, |triangles|, max_bit)
```

| 特性 | SAH BVH | LBVH |
|:---|:---|:---|
| **构建速度** | $O(n \log^2 n)$ | $O(n \log n)$（排序瓶颈） |
| **遍历质量** | ✅ 最优（SAH 优化） | ⚠️ 近似（可能不如 SAH） |
| **并行性** | ❌ 串行递归 | ✅ 高度并行（适合 GPU） |
| **GPU 构建** | 困难 | ✅ 原生支持 |

LBVH 特别适合 GPU 上的**实时重建**场景——例如动态物体的 BVH 在每帧更新。

## 5. SIMD 与 GPU 并行化

### 5.1 SIMD（单指令多数据）

CPU 上的 SIMD（SSE/AVX）可以同时处理多条光线：

```
// AVX：同时处理 8 条光线
__m256 ox = {ray[0].ox, ray[1].ox, ..., ray[7].ox};  // 8 个 x 原点
__m256 oy = {ray[0].oy, ray[1].oy, ..., ray[7].oy};  // 8 个 y 原点
// 一条指令完成 8 条光线的 AABB 相交测试
__m256 tmin = AABB_Intersect_8(ox, oy, oz, dx, dy, dz, bmin, bmax);
```

**Packet Tracing**：将多条光线打包为一组，同时对 BVH 的一个节点进行相交测试。当多条光线访问相同的 BVH 节点时，可以共享内存访问，减少 cache miss。

### 5.2 GPU 并行化

GPU 拥有数千个计算核心，天然适合光线追踪的**大规模并行**——每个像素/每条路径可以独立计算。

**挑战与优化**：

| 挑战 | 原因 | 优化策略 |
|:---|:---|:---|
| **分支分化** | 不同路径的递归深度不同 | 减少分支，使用 wave-wide 操作 |
| **内存访问** | BVH 遍历的访问模式不可预测 | 节点线性存储，合并访存 |
| **栈管理** | 递归遍历需要栈 | 使用紧凑的短栈（Wavefront tracing） |
| **构建 BVH** | GPU 上构建 BVH 较复杂 | 使用 LBVH / HLSBVH |

### 5.3 现代 GPU 光追

2018 年 NVIDIA RTX 20 系列引入了**硬件光线追踪（RT Cores）**：

- **专用 BVH 遍历单元**：硬件加速射线-AABB 和射线-三角形相交测试
- **API 支持**：DXR（DirectX Raytracing）、Vulkan Ray Tracing、OptiX
- **性能**：相比纯软件实现，BVH 遍历加速约 10 倍

```
现代实时光追管线：
  GPU Compute Shader / Ray Generation Shader
    → 发射光线（TraceRay）
      → RT Core: BVH 遍历 + 三角形求交（硬件加速）
        → Hit/Miss Shader: 着色计算
          → 可能继续发射新光线（递归）
```

## 总结

$$\boxed{\text{Whitted 光追}} \xrightarrow{\text{物理化}} \boxed{\text{路径追踪（蒙特卡洛）}} \xrightarrow{\text{加速}} \boxed{\text{BVH + SAH + SIMD/GPU}}$$

| 主题 | 核心内容 |
|:---|:---|
| **Whitted 光追** | 递归光线追踪、反射/折射、阴影射线 |
| **路径追踪** | 渲染方程、蒙特卡洛积分、BRDF、俄罗斯轮盘赌 |
| **BVH vs KD Tree** | BVH 更适合动态场景和 GPU |
| **SAH** | 表面积启发式代价模型，指导最优分割 |
| **Morton Code / LBVH** | 空间编码 + 线性 BVH，GPU 友好 |
| **SIMD / GPU** | 数据并行、Packet Tracing、RT Core 硬件加速 |
