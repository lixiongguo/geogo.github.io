## 1. 美术馆问题

### 1.1 问题定义

**美术馆问题（Art Gallery Problem）**，又称博物馆问题，是计算几何中的一个经典可见性问题：

> 给定一个具有 $n$ 个顶点的简单多边形，最少需要多少个守卫（camera）才能监控整个多边形内部？守卫是固定在某位置的点，可以看到其视线不被多边形边界阻挡的所有区域。

这个问题由 Victor Klee 在 1973 年正式提出。

### 1.2 Chvátal 定理（美术馆定理）

**Chvátal 定理（1975）**：对于任何具有 $n$ 个顶点的简单多边形，$\lfloor n/3 \rfloor$ 个守卫**总是充分的**，且对某些多边形**是必要的**。

$$\text{最少守卫数} \leq \left\lfloor \frac{n}{3} \right\rfloor$$

### 1.3 Fisk 的 3-着色证明

Fisk（1978）给出了一个非常优美的证明，关键步骤如下：

**第一步：三角剖分**

将多边形进行三角剖分（$n-2$ 个三角形，$n-3$ 条对角线）。

**第二步：3-可着色**

证明三角剖分后的对偶图（将三角形视为节点，相邻三角形之间有边）是**3-可着色的**：

> **定理**：任何简单多边形的三角剖分都可以用 3 种颜色给顶点着色，使得每个三角形的三个顶点颜色各不相同。

**第三步：鸽巢原理**

根据鸽巢原理，3 种颜色中至少有一种颜色使用的顶点数不超过 $\lfloor n/3 \rfloor$。将守卫放在这种颜色的所有顶点上，由于每个三角形都包含所有三种颜色的顶点，因此每个三角形都被至少一个守卫看到。

$$\max\left(\left|C_1\right|, \left|C_2\right|, \left|C_3\right|\right) \leq \left\lfloor \frac{n}{3} \right\rfloor$$

**为什么 3-可着色成立？** 三角剖分后的图是一个**平面图**（对偶图也是平面图），每个顶点的度数至少为 2（除了两个端点）。由平面图的性质，任意三角形网格都是 3-可着色的。

## 2. 割耳法

### 2.1 基本概念

**耳（Ear）**：简单多边形中，由三个连续顶点 $v_{i-1}, v_i, v_{i+1}$ 构成的三角形，满足以下条件：
1. 对角线 $v_{i-1}v_{i+1}$ 完全位于多边形**内部**
2. 该三角形内部不包含多边形的任何其他顶点

直观地说，"耳"就是多边形边界上一个**可以安全切掉的三角形尖角**。

### 2.2 双耳定理

**Meisters 双耳定理（Two-Ears Theorem, 1975）**：

> 除了三角形以外的**每一个**简单多边形都**至少有两个不重叠的耳**。

这意味着割耳法永远不会陷入没有耳可切的困境。

### 2.3 割耳法算法

```
function EarClipping(Polygon):
    // 输入：n 个顶点的简单多边形（按逆时针排列）
    // 输出：n-2 个三角形

    Initialize triangle list = []
    vertexList = Polygon.vertices (按顺序)

    while |vertexList| > 3:
        // 寻找一个耳
        earFound = false
        for i = 1 to |vertexList| - 1:  // 跳过首尾
            v_prev = vertexList[i-1]
            v_curr = vertexList[i]
            v_next = vertexList[i+1]

            if IsConvex(v_prev, v_curr, v_next) AND
               IsDiagonalInside(v_prev, v_next) AND
               NoVertexInsideTriangle(v_prev, v_curr, v_next):
                // 找到一个耳！
                Add triangle (v_prev, v_curr, v_next) to list
                Remove v_curr from vertexList
                earFound = true
                break

        if not earFound:
            Error("No ear found - not a simple polygon")

    // 剩下三个顶点构成最后一个三角形
    Add last triangle to list
    return triangle list
```

### 2.4 辅助判断

**凸顶点判断**：给定三个连续顶点 $v_{i-1}, v_i, v_{i+1}$，用叉积判断 $v_i$ 是否为凸顶点：

$$\text{cross} = (v_i - v_{i-1}) \times (v_{i+1} - v_i)$$

- $\text{cross} > 0$（逆时针方向）：$v_i$ 是**凸顶点**（内角 $< 180°$）
- $\text{cross} < 0$：$v_i$ 是**凹顶点**（内角 $> 180°$）
- $\text{cross} = 0$：三点共线

**对角线在多边形内部**：对角线 $v_{i-1}v_{i+1}$ 不与多边形的任何边相交，且位于多边形内部。

**无其他顶点在三角形内**：三角形的内部不包含多边形的任何其他顶点。

### 2.5 复杂度分析

| 操作 | 时间复杂度 |
|:---|:---|
| 寻找一个耳 | $O(n)$（检查 $n$ 个顶点） |
| 判断对角线在内部 | $O(n)$（与所有边比较） |
| 判断无顶点在三角形内 | $O(n)$ |
| **一轮切耳** | $O(n)$ |
| **总复杂度** | **$O(n^2)$**（$n-2$ 轮，每轮 $O(n)$） |

### 2.6 优化

通过使用**双端队列**（同时从两端搜索耳），可以将平均复杂度降低，但最坏情况仍为 $O(n^2)$。使用更高效的数据结构（如将多边形表示为双向链表 + 跳表），最坏情况可以优化到 $O(n \log \log n)$。

## 3. 单调多边形法

### 3.1 单调多边形的定义

**单调多边形（Monotone Polygon）**：存在一条直线方向（如 $y$ 轴），使得任何垂直于该方向的直线与多边形的交恰好是一个**连续的线段**。

换言之，从多边形的**上链**和**下链**各遍历一次，就能走完整个多边形边界。

大多数"合理"的多边形（如凸多边形、星形多边形）都是单调的。但有些简单多边形不是单调的，例如"螺旋形"多边形。

### 3.2 判断单调性

一个多边形关于 $y$ 轴单调，当且仅当：从最高点到最低点沿边界走，$y$ 坐标先严格递减，然后再严格递增（可以有"平"的部分）。

### 3.3 $O(n \log n)$ 三角剖分算法

对于单调多边形，可以使用**扫描线算法**在 $O(n \log n)$ 时间内完成三角剖分。

**算法流程**：

```
function TriangulateMonotone(Polygon):
    // 步骤1：将多边形分解为上链和下链
    找到 y 坐标最高和最低的顶点
    将边界分为上链（从高到低，y 单调递减）和下链（从高到低，y 单调递增）

    // 步骤2：按 y 坐标排序所有顶点
    Sort all vertices by y-coordinate (descending)

    // 步骤3：扫描线处理
    Initialize stack
    Push first two vertices onto stack

    for each vertex v (from third to last, in sorted order):
        if v is on the opposite chain from stack top:
            // v 和栈顶在不同链上：连接 v 和栈中所有顶点
            while |stack| > 1:
                Add diagonal (v, stack.top)
                Pop stack
            Push stack.top back  // 保留栈底
            Push v
        else:
            // v 和栈顶在同一链上
            Pop last vertex u from stack
            while stack is not empty:
                if diagonal (v, stack.top) is inside polygon:
                    Add diagonal (v, stack.top)
                    u = Pop stack
                else:
                    break
            Push u
            Push v

    return diagonals
```

### 3.4 复杂度分析

| 步骤 | 时间复杂度 |
|:---|:---|
| 分解上链/下链 | $O(n)$ |
| 排序顶点 | $O(n \log n)$ |
| 扫描线处理 | $O(n)$（每个顶点最多入栈/出栈一次） |
| **总复杂度** | **$O(n \log n)$** |

### 3.5 通用多边形三角剖分

对于非单调的一般简单多边形，可以通过两步实现 $O(n \log n)$ 三角剖分：

1. **单调化**：在 $O(n)$ 时间内将任意简单多边形分解为 $y$-单调多边形（Garey et al., 1978）
2. **单调剖分**：对每个单调子多边形用 $O(n \log n)$ 算法进行三角剖分

$$T(n) = O(n) + O(n \log n) = O(n \log n)$$

## 4. 可视图与游戏中的导航网格

### 4.1 可视图（Visibility Graph）

**可见图**是计算几何中用于可见性分析的基本数据结构：

> 在多边形环境（或多边形障碍物集合）中，可见图的顶点是环境中多边形的所有顶点，两个顶点之间存在边当且仅当它们彼此"可见"（即连接它们的线段不与环境边界相交）。

**形式化定义**：

$$G_{\text{vis}} = (V, E)$$

$$E = \{(v_i, v_j) : \overline{v_i v_j} \cap \text{int}(\partial P) = \emptyset \}$$

其中 $\partial P$ 是多边形的边界。

### 4.2 可视图的构造

**朴素构造**：检查所有 $\binom{n}{2} = O(n^2)$ 对顶点的可见性，每对检查需要 $O(n)$ 时间（与所有边比较），总复杂度 $O(n^3)$。

**最优算法**：Overmars 和 Welzl（1988）提出了 $O(n^2)$ 的构造算法。

**可见图的性质**：

| 性质 | 说明 |
|:---|:---|
| **顶点数** | $n$（多边形的所有顶点） |
| **边数** | $O(n)$（最坏情况 $O(n^2)$） |
| **平面性** | 不一定是平面图 |
| **完备性** | 可视图包含最短路径的所有边 |

### 4.3 最短路径与可见图

可见图的一个重要应用是**多边形内部的最短路径**：

> **定理**：简单多边形内部任意两点之间的最短路径，一定是可见图的路径。

因此，在可见图上使用 Dijkstra 算法，即可找到多边形内部的最短路径，复杂度为 $O(n^2 \log n)$。

### 4.4 游戏中的导航网格

在游戏开发中，**导航网格（Navigation Mesh, NavMesh）** 是 AI 角色寻路的核心数据结构。

#### 4.4.1 什么是导航网格

导航网格将游戏场景中的**可行走区域**表示为一组凸多边形（通常是三角形）。每个凸多边形代表一个"可以自由移动的区域"。

**为什么用凸多边形？** 因为在凸多边形内部，任意两点之间的直线段一定在多边形内部——这意味着角色可以在凸多边形内**直线移动**，无需绕弯。

#### 4.4.2 导航网格的构建

```
// 简化的 NavMesh 构建流程

1. 从游戏场景中提取可行走区域（可行走多边形）
2. 将可行走多边形三角剖分（Delaunay 或约束三角剖分）
3. 构建邻接图：相邻三角形之间有边
4. 可选：计算可见性信息，用于更精确的路径平滑
```

#### 4.4.3 基于 NavMesh 的寻路

**步骤一：A* 寻路（粗粒度）**

在导航网格的三角形邻接图上使用 A* 算法，找到从起点三角形到终点三角形的**三角形序列**。

代价函数：
- **g(n)**：从起点到当前三角形的代价（相邻三角形之间的移动代价）
- **h(n)**：启发式估计（如到目标三角形的欧氏距离）

**步骤二：路径平滑（细粒度）**

三角形序列的边界上的转折点可能看起来很不自然（"之字形"）。使用 **Funnel Algorithm（漏斗算法）** 进行路径平滑：

1. 将三角形序列构建为一个"漏斗"（Funnel）
2. 从起点到终点，逐步收紧漏斗
3. 得到一条光滑的、贴合障碍物边缘的最短路径

**步骤三：Steering**

角色沿平滑路径移动时，使用转向行为（Steering Behaviors）使运动更自然：
- 避障（Obstacle Avoidance）
- 群体行为（Flocking / Separation）
- 速度匹配（Velocity Matching）

### 4.5 导航网格 vs 其他寻路方法

| 方法 | 表示粒度 | 内存 | 寻路质量 | 动态更新 | 适用场景 |
|:---|:---|:---|:---|:---|:---|
| **网格寻路（Grid）** | 方格 | 大 | 较粗糙 | ✅ 容易 | 2D/简单地形 |
| **导航网格（NavMesh）** | 凸多边形 | 中 | ✅ 精确 | ⚠️ 中等 | 3D/复杂地形 |
| **可见图** | 顶点 | 小 | ✅ 最优路径 | ❌ 困难 | 室内/简单障碍 |
| **导航体积（NavVolume）** | 体素 | 很大 | 精确 | ✅ 容易 | 复杂 3D |
| **四叉树/八叉树** | 层次网格 | 中 | 中等 | ✅ 容易 | 大开放区域 |

### 4.6 实际游戏引擎中的实现

现代游戏引擎（Unity、Unreal Engine）都内置了 NavMesh 系统：

- **Unity NavMesh**：基于 Recast/Detour 库，支持动态障碍物、多 Agent 避障
- **Unreal Engine NavMesh**：支持体素化构建、自动生成、实时更新

核心库 **Recast**（Mikko Mononen）的构建流程：
1. 将可行走区域**体素化**（Voxelization）
2. 提取等值面生成**轮廓**（Contour）
3. 将轮廓**三角化**（Triangulation）得到 NavMesh
4. 构建邻接图和区域连接（Region Connection）

## 总结

| 主题 | 核心算法 | 复杂度 | 应用 |
|:---|:---|:---|:---|
| **美术馆问题** | 三角剖分 + 3-着色 + 鸽巢原理 | $\lfloor n/3 \rfloor$ | 监控、设施布局 |
| **割耳法** | 逐步切耳 | $O(n^2)$ | 通用三角剖分 |
| **单调多边形法** | 扫描线 + 栈 | $O(n \log n)$ | 快速三角剖分 |
| **可见图** | 顶点对可见性检查 | $O(n^3)$（朴素）/ $O(n^2)$（最优） | 最短路径、可视性分析 |
| **导航网格** | 三角剖分 + A* + Funnel 平滑 | $O(n \log n)$ 构建 | 游戏 AI 寻路 |
