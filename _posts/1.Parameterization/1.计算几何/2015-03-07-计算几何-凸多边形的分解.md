## 1. 美术问题：为什么要三角剖分？

### 1.1 问题的起源

想象一个美术馆（或博物馆），形状是一个具有 $n$ 个顶点的简单多边形。馆长希望用最少的摄像头来监控整个展厅的每一个角落。每个摄像头固定在某一点，能看到其视线不被墙壁阻挡的所有区域。

**美术馆问题（Art Gallery Problem, Klee 1973）**：给定一个 $n$ 顶点简单多边形，最少需要多少个守卫才能监控其全部内部？

这个问题看似与三角剖分无关，但答案恰恰依赖于三角剖分。

### 1.2 Chvátal 定理（1975）

**美术馆定理**：对于任意 $n$ 顶点的简单多边形，$\lfloor n/3 \rfloor$ 个守卫**总是足够的**，且对某些多边形**是必要的**。

$$\text{最少守卫数} \leq \left\lfloor \frac{n}{3} \right\rfloor$$

### 1.3 证明的核心——三角剖分

Fisk（1978）给出了一个极其优美的证明，其**第一步就是将多边形三角剖分**：

> **证明思路**：
> 1. 将多边形三角剖分为 $n-2$ 个三角形
> 2. 证明三角剖分图的顶点可以 **3-可着色**（每个三角形的三个顶点颜色各异）
> 3. 由鸽巢原理，至少一种颜色 $\leq \lfloor n/3 \rfloor$ 个顶点——在此处放守卫即可覆盖所有三角形

三角剖分是证明的关键桥梁。没有三角剖分，就没有 3-着色；没有 3-着色，就无法应用鸽巢原理。因此，**如何高效地将多边形三角剖分**成为了计算几何的一个 fundamental problem。

更进一步，在计算机图形学中，三角形是最基本的图元——GPU 只能渲染三角形。任何多边形在送入 GPU 之前都必须被三角剖分。这赋予了三角剖分不仅是理论意义，更是**工程上的刚需**。

### 1.4 三角剖分的形式化定义

给定一个 $n$ 顶点的简单多边形 $P = (v_0, v_1, \ldots, v_{n-1})$，三角剖分是将 $P$ 划分为 $n-2$ 个不相交的三角形，通过添加 $n-3$ 条**互不相交的对角线**实现。

> **对角线（Diagonal）**：连接多边形两个不相邻顶点的线段，完全位于多边形内部。

$$T = \{\triangle_1, \triangle_2, \ldots, \triangle_{n-2}\}$$

## 2. 朴素方法：割耳法

### 2.1 从直观出发

最直观的三角剖分策略是：找到多边形边界上"凸出来"的角，切掉它形成的三角形，剩下的还是一个更小的多边形——重复直到只剩一个三角形。

这就是**割耳法（Ear Clipping）**的核心思想。

### 2.2 耳的定义

**耳（Ear）**：由多边形三个连续顶点 $v_{i-1}, v_i, v_{i+1}$ 构成的三角形 $\triangle v_{i-1}v_iv_{i+1}$，满足：

1. 对角线 $v_{i-1}v_{i+1}$ 完全位于多边形内部
2. 该三角形内部不包含多边形的任何其他顶点

直观地说，耳就是多边形边界上凸出的"尖角"。

### 2.3 双耳定理——算法不会卡死

一个自然的问题是：会不会某个多边形没有耳可切？

**Meisters 双耳定理（Two-Ears Theorem, 1975）**：

> 除三角形以外的**每一个**简单多边形都**至少有两个不重叠的耳**。

这保证了割耳法永远不会陷入死局——总能找到耳来切。

### 2.4 割耳法算法

```
function EarClipping(Polygon):
    triangleList = []
    vertexList = Polygon.vertices  // 逆时针排列

    while |vertexList| > 3:
        for each vertex v_i in vertexList (跳过首尾):
            v_prev, v_next = v_i 的前后邻居
            if v_i 是凸顶点 AND
               对角线 v_prev-v_next 在多边形内部 AND
               三角形(v_prev, v_i, v_next) 内无其他顶点:
                // v_i 是一个耳，切掉它
                Add triangle (v_prev, v_i, v_next) to triangleList
                Remove v_i from vertexList
                break

    // 最后三个顶点就是最后一个三角形
    return triangleList  // 共 n-2 个三角形
```

### 2.5 辅助判断

**凸顶点判断**（叉积）：

$$\text{cross}(v_{i-1}, v_i, v_{i+1}) = (v_i - v_{i-1}) \times (v_{i+1} - v_i)$$

$\text{cross} > 0$（逆时针）→ 凸顶点；$\text{cross} < 0$ → 凹顶点。

### 2.6 复杂度分析

| 操作 | 时间 |
|:---|:---|
| 判断一个顶点是否为耳 | $O(n)$（检查所有边和所有顶点） |
| 一轮切耳 | $O(n)$ |
| **总计（$n-2$ 轮）** | **$O(n^2)$** |

$O(n^2)$ 对于小规模多边形完全可以接受，但对于大规模网格（$n > 10^4$）就显得力不从心了。我们需要更高效的方法。

## 3. 高效方法：单调多边形三角剖分

### 3.1 关键观察

割耳法的瓶颈在于：每找一次耳都要扫描 $O(n)$ 个顶点，而总共需要切 $n-2$ 次耳。能否**一次扫描**就完成整个三角剖分？

答案是可以的——**但仅限于单调多边形**。

### 3.2 单调多边形的定义

**单调多边形（Monotone Polygon）**：存在一条方向（如 $y$ 轴），使得任何垂直于该方向的直线与多边形的交恰好是一个**连续线段**。

等价地说，多边形的边界可以分解为两条**单调链**（Monotone Chain）：
- **上链**：从最高点到最低点沿一条方向遍历，$y$ 坐标单调递减
- **下链**：从最高点到最低点沿另一方向遍历，$y$ 坐标单调递增

大多数"正常形状"的多边形（凸多边形、星形多边形等）都是单调的，但"螺旋形"多边形不是。

### 3.3 为什么单调性帮助三角剖分？

直觉：在单调多边形中，从上到下扫描时，我们总是确切知道"哪些顶点在左边链上、哪些在右边链上"。这消除了割耳法中"检查对角线是否在内部"这一昂贵步骤——在单调多边形中，只要两个顶点分属不同链且扫描顺序正确，连接它们就是对角线。

### 3.4 $O(n \log n)$ 扫描线算法

```
function TriangulateMonotone(Polygon):
    // 步骤1：分解上链和下链
    找到 y 最高的顶点 (两个链的起点)
    找到 y 最低的顶点 (两个链的终点)
    将边界分为上链 U (y 单调递减) 和下链 L (y 单调递增)

    // 步骤2：按 y 坐标排序
    vertices = Sort(Polygon.vertices, by y, descending)

    // 步骤3：扫描线处理
    stack = [vertices[0], vertices[1]]
    for i = 2 to n-1:
        v = vertices[i]
        if v 与 stack.top 在不同链上:
            // v 和栈顶分属不同链 → 一次性连接所有可行对角线
            while |stack| > 1:
                Add diagonal (v, stack.top)
                Pop stack
            Push v
        else:
            // v 和栈顶在同一链上 → 逐个检查
            last = Pop stack
            while stack is not empty:
                if diagonal(v, stack.top) 在多边形内部:
                    Add diagonal (v, stack.top)
                    last = Pop stack
                else:
                    break
            Push last, Push v

    return diagonals
```

### 3.5 复杂度分析

| 步骤 | 时间 |
|:---|:---|
| 分解上链/下链 | $O(n)$ |
| 按 $y$ 排序 | $O(n \log n)$ ← **瓶颈** |
| 扫描线处理 | $O(n)$（每个顶点最多入栈出栈常数次） |
| **总计** | **$O(n \log n)$** |

相比割耳法的 $O(n^2)$，这是一个本质性的提升。

### 3.6 通用多边形的三角剖分

对于非单调的一般简单多边形，可以通过两步达到 $O(n \log n)$：

1. **单调化**（$O(n)$）：将任意简单多边形分割为 $y$-单调子多边形（Garey et al., 1978）
2. **单调剖分**（$O(n \log n)$）：对每个单调子多边形用扫描线算法三角剖分

$$T(n) = O(n) + O(n \log n) = O(n \log n)$$

## 4. 应用：可视图与导航网格

### 4.1 从三角剖分到路径规划

三角剖分是手段而非目的。在实际应用中（尤其是游戏开发），我们关心的终极问题是：**给定起点和终点，如何在多边形环境中找到一条最短/近似最短的路径？**

这就引出了从三角剖分到导航网格的完整链条：

$$\underbrace{\text{多边形}}_{\text{原始输入}} \xrightarrow{\text{三角剖分}} \underbrace{\text{三角形网格}}_{\text{空间表示}} \xrightarrow{\text{可视图}} \underbrace{\text{路径图}}_{\text{路径搜索}} \xrightarrow{\text{A*}} \underbrace{\text{最优路径}}_{\text{最终目标}}$$

### 4.2 第一步：多边形分解与三角剖分

将场景中的可行走区域（一个或多个简单多边形）进行三角剖分，得到 $O(n)$ 个三角形。这一步正是前面讨论的三角剖分问题。

三角形被选择为基本单元的原因：**凸多边形内的任意两点可以直接连线到达**，这意味着角色在三角形内可以自由直线移动，无需考虑障碍。

### 4.3 第二步：构建可视图（Visibility Graph）

**可视图**定义如下：

$$G_{\text{vis}} = (V, E), \quad V = \{\text{多边形所有顶点}\}$$

$$E = \{(v_i, v_j) : \overline{v_i v_j} \cap \text{int}(\partial P) = \emptyset \}$$

即两个顶点之间有边当且仅当它们之间的连线不穿过任何障碍物。

**关键定理**：

> **最短路径定理**：简单多边形内部任意两点之间的最短路径，其所有拐点都是多边形的顶点。因此，最短路径一定是可视图中的一条路径。

这意味着在可视图上做最短路径搜索是**精确的**。

**构造复杂度**：
- 朴素方法：检查 $O(n^2)$ 对顶点，每对 $O(n)$ → $O(n^3)$
- 最优方法（Overmars & Welzl, 1988）：$O(n^2)$

### 4.4 第三步：在导航图上运行 A* 算法

有了可视图之后，寻路问题就变成了图上的最短路径问题。使用 **A\* 算法**：

$$f(n) = g(n) + h(n)$$

- **$g(n)$**：从起点到当前节点的**实际代价**（在可视图中即为欧氏距离之和）
- **$h(n)$**：从当前节点到终点的**启发式估计**（通常取欧氏距离，满足可容许性）

A* 在可视图上的复杂度：图有 $O(n)$ 条边，优先队列操作 $O(\log n)$，总复杂度 $O(n^2 \log n)$。

### 4.5 第四步：路径平滑（Funnel Algorithm）

A* 在可视图上找到的路径经过多边形的顶点，看起来是"之字形"的折线。为了得到视觉上更自然的路径，需要**路径平滑**。

**漏斗算法（Funnel Algorithm）**：

1. A* 返回的路径对应一个**三角形序列**
2. 将这个三角形序列想象成一个从起点到终点的"漏斗"（Funnel）
3. 从起点到终点逐步收紧漏斗的宽度，得到最短路径
4. 路径上的每一段都是贴着障碍物边缘的直线段

漏斗算法的时间复杂度为 $O(n)$（线性于路径经过的三角形数量）。

### 4.6 导航网格（Navigation Mesh）在游戏中的实现

现代游戏引擎（Unity、Unreal Engine）将上述理论整合为 **NavMesh** 系统：

```
构建阶段（预处理）：
  可行走区域 → 体素化(Voxelization) → 轮廓提取(Contour) → 三角剖分 → 邻接图

运行时寻路：
  起点/终点 → 定位所属三角形 → A* 在三角形邻接图上搜索 → Funnel 平滑 → 路径输出
```

| 方法 | 表示粒度 | 寻路质量 | 构建复杂度 | 适用场景 |
|:---|:---|:---|:---|:---|
| **网格寻路（Grid）** | 方格 | 粗糙（受网格粒度限制） | $O(1)$ | 简单 2D 地形 |
| **导航网格（NavMesh）** | 凸多边形 | ✅ 精确（平滑路径） | $O(n \log n)$ | 3D/复杂地形 |
| **可视图** | 顶点 | ✅ 理论最优 | $O(n^2) \sim O(n^3)$ | 室内/简单障碍 |
| **四叉树/八叉树** | 层次网格 | 中等 | $O(n)$ | 大开放区域 |

## 总结

本文的逻辑链条如下：

$$\boxed{\text{美术馆问题}} \xrightarrow{\text{理论需求}} \boxed{\text{三角剖分}} \xrightarrow{\text{算法演进}} \boxed{\text{割耳法} \to \text{单调多边形法}}$$

$$\boxed{\text{三角剖分}} \xrightarrow{\text{空间表示}} \boxed{\text{导航网格}} \xrightarrow{\text{路径规划}} \boxed{\text{可视图} \to \text{A*} \to \text{Funnel 平滑}}$$

| 主题 | 角色 | 复杂度 | 关键定理 |
|:---|:---|:---|:---|
| **美术馆问题** | 理论动机 | — | Chvátal: $\lfloor n/3 \rfloor$ 守卫 |
| **割耳法** | 朴素三角剖分 | $O(n^2)$ | 双耳定理 |
| **单调多边形法** | 高效三角剖分 | $O(n \log n)$ | 排序瓶颈 |
| **可视图** | 精确路径搜索 | $O(n^2)$ 构造 | 最短路径经过顶点 |
| **NavMesh + A*** | 工程实践 | $O(n \log n)$ 构建 | Funnel 路径平滑 |
