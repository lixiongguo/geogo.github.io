强化学习训练环境与算法总结
2026/04/03

本文总结了四个典型强化学习训练环境的核心挑战与对应算法：五子棋（Alpha-Beta 搜索）、围棋（AlphaGo）、Atari 游戏（DQN）和 RoboCup 2D 足球仿真。

1. 五子棋 —— Alpha-Beta 搜索

训练环境

五子棋是一个完全信息、零和、确定性的博弈游戏：

  • 棋盘通常为 15×15 或 19×19
  • 状态空间：$\approx 3^{225}$（15×15 棋盘，每格 空/黑/白）
  • 分支因子：初始时约 225，逐步减少
  • 游戏长度：通常 50~100 步

核心问题

问题 说明
搜索空间爆炸 即使 15×15 棋盘，完全搜索也不可行
评估函数设计 如何判断一个中间局面”有多好”
搜索效率 Minimax 的完全搜索树太大，需要有效剪枝
模式识别 识别活四、冲四、活三等棋型是关键

对应算法：Alpha-Beta 剪枝

Minimax 算法是博弈论中的经典方法——假设双方都做最优决策，交替搜索使己方最大收益、对方最小收益。

Alpha-Beta 剪枝在 Minimax 基础上引入两个阈值：

  • $\alpha$：当前 MAX 节点已知的下界（”至少能拿这么多”）
  • $\beta$：当前 MIN 节点已知的上界（”最多只会给这么多”）

剪枝规则：当 $\alpha \geq \beta$ 时，该分支不可能影响最终结果，直接剪掉。

function AlphaBeta(node, depth, α, β, maximizingPlayer):
    if depth = 0 or node is terminal:
        return Evaluate(node)
    if maximizingPlayer:
        value = -∞
        for each child of node:
            value = max(value, AlphaBeta(child, depth-1, α, β, false))
            α = max(α, value)
            if α ≥ β:  // β 剪枝
                break
        return value
    else:
        value = +∞
        for each child of node:
            value = min(value, AlphaBeta(child, depth-1, α, β, true))
            β = min(β, value)
            if α ≥ β:  // α 剪枝
                break
        return value

最佳情况复杂度：$O(b^{d/2})$，其中 $b$ 为分支因子，$d$ 为搜索深度。相比 Minimax 的 $O(b^d)$，节省了一个平方根级的搜索量。

五子棋中的增强技巧：

  • 启发式排序：优先搜索更”有希望”的走法（如进攻/防守关键点），最大化剪枝效率
  • 迭代加深：先用浅层搜索，再用深层搜索，利用浅层结果指导深层排序
  • 置换表（Transposition Table）：缓存已搜索的局面，避免重复计算
  • 棋型评估：对活四、冲四、活三等棋型赋予不同分值

局限性：Alpha-Beta 的效果高度依赖评估函数的质量和走法排序。对于更强的五子棋 AI，可以结合蒙特卡洛树搜索（MCTS） 或 AlphaZero 风格的深度强化学习。

2. 围棋 —— AlphaGo

训练环境

围棋是最具挑战性的棋类游戏之一：

  • 棋盘 19×19，每格有 3 种状态（空/黑/白）
  • 状态空间：$\approx 10^{170}$（远超宇宙原子数 $\sim 10^{80}$）
  • 分支因子：平均约 250（远大于象棋的 ~35）
  • 游戏长度：约 200~250 步

核心问题

问题 说明
状态空间巨大 $10^{170}$，暴力搜索完全不可能
分支因子极高 平均 ~250，Alpha-Beta 剪枝效果极差
评估困难 围棋没有简单的局面评估标准（不像象棋可数子）
长期策略 好棋可能在几十步后才显示其价值
“厚度”等模糊概念 围棋中”势”“厚度”“味道”等概念难以形式化

对应算法：AlphaGo（深度 RL + MCTS）

AlphaGo（Silver et al., Nature 2016）是首个击败人类职业棋手的围棋 AI，其核心是将深度学习与蒙特卡洛树搜索（MCTS） 创新结合。

训练流程（三阶段）：

阶段1: 监督学习（Supervised Learning, SL）
├── 输入：KGS 围棋服务器上 3000 万步人类专家对弈记录
├── 训练：SL Policy Network p_σ
│   └── 输入：当前棋盘状态 → 输出：下一步落子的概率分布
├── 目标：预测人类专家的走法（准确率 57%）
└── 产物：一个能模仿人类下棋的神经网络

阶段2: 强化学习（Reinforcement Learning, RL）
├── 用 SL Policy Network 初始化 RL Policy Network p_ρ
├── 训练方法：Policy Gradient（策略梯度）
│   └── p_ρ 与自己之前的版本对弈
│   └── 赢了 → 增强当前策略，输了 → 减弱
├── 目标：最大化对弈胜率（而非模仿人类）
└── 产物：一个比 SL Network 更强的策略网络

阶段3: 价值网络（Value Network, V）
├── 从 RL Policy Network 的自我对弈中抽取 3000 万个局面
├── 训练：Value Network v_θ
│   └── 输入：棋盘状态 → 输出：胜率 [-1, +1]
├── 关键：每个对局只取一个局面（避免相关局面过拟合）
└── 产物：一个能评估局面好坏的神经网络

AlphaGo 使用四个网络：

网络 作用 训练方式
Rollout Policy（快速策略） MCTS 中的快速模拟 线性 softmax，小特征集
SL Policy Network MCTS 的先验概率 监督学习（人类数据）
RL Policy Network 自我对弈的策略提升 策略梯度强化学习
Value Network 评估叶节点价值 监督学习（RL 自我对弈数据）

蒙特卡洛树搜索（MCTS）与神经网络结合：

AlphaGo 的 MCTS 选择走法时综合了神经网络的判断：

\[P(s, a) = (1 - \lambda) p_\sigma(a|s) + \lambda \text{rollout}(s)\]

其中 $\lambda$ 平衡了 SL Policy Network 的预测和快速 rollout 的结果。叶节点的价值评估为：

\[V(s_L) = (1 - \alpha) v_\theta(s_L) + \alpha z_L\]

综合了 Value Network 的预测 $v_\theta$ 和 MCTS 模拟的胜负结果 $z_L$。

为什么 AlphaGo 能成功：

  1. 深度学习提供了”直觉”：Policy Network 给出有潜力的候选走法，大幅减少了搜索空间
  2. MCTS 提供了”思考”：在关键局面深入搜索，弥补了网络判断的不足
  3. Value Network 提供了”评估”：替代了传统围棋中不可能设计的精确评估函数
  4. 自我对弈的强化学习：让 AI 不断突破人类棋谱的局限

3. Atari 游戏 —— DQN

训练环境

Atari 2600 游戏是深度强化学习的经典测试平台（Bellemare et al., 2013）：

  • 输入：原始像素画面（210×160×3 RGB）
  • 动作：操纵杆方向 + 按钮组合（通常 4~18 个离散动作）
  • 奖励：游戏得分（稀疏、延迟、噪声）
  • 特点：完全可观测、部分可随机、单智能体

核心问题

问题 说明
高维输入 原始像素是高维连续信号，难以直接处理
部分可观测 单帧画面不包含运动信息（球的速度方向等）
奖励稀疏/延迟 关键奖励可能在很远的将来才出现
信用分配 哪些历史决策导致了当前奖励？
训练不稳定 深度网络 + RL 导致严重的” Deadly Triad”问题

对应算法：DQN（Deep Q-Network）

DQN（Mnih et al., Nature 2015）首次证明了深度神经网络可以直接从高维感知输入（原始像素）学习控制策略，在 29 个 Atari 游戏中达到或超过人类水平。

核心思想：用深度神经网络近似 Q 函数 $Q(s, a)$——在状态 $s$ 下执行动作 $a$，预期能获得的总奖励。

Q-Learning 回顾：

\[Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha \left[ r_t + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t) \right]\]

DQN 的两大关键创新：

1. 经验回放（Experience Replay）

将智能体的经验 $(s_t, a_t, r_t, s_{t+1})$ 存入回放缓冲区，训练时从中随机采样。

replay_buffer = []  # 存储转移 (s, a, r, s')

# 交互阶段：存入经验
replay_buffer.append((s, a, r, s_next))

# 训练阶段：随机采样小批量
batch = random.sample(replay_buffer, batch_size)

作用：

  • 打破数据相关性：连续经验之间高度相关，直接训练会导致网络不稳定
  • 提高数据利用效率：每条经验可以被多次使用
  • 平滑数据分布：随机采样使训练数据分布更接近 i.i.d.

2. 目标网络（Target Network）

使用一个独立的、参数定期更新的目标网络计算 TD 目标：

\[y = r + \gamma \max_{a'} Q_{\theta^-}(s', a')\]

其中 $\theta^-$ 是目标网络参数，每隔 $C$ 步才从主网络复制一次：$\theta^- \leftarrow \theta$。

作用：

  • 稳定训练目标：如果用同一个网络计算目标值和当前值，目标会随着训练不断移动，导致”追着移动目标跑”的不稳定

DQN 完整训练流程：

初始化 Q 网络 Q(s,a; θ)（随机权重）
初始化目标网络 Q̂(s,a; θ⁻)（θ⁻ = θ）
初始化经验回放缓冲区 D

for episode = 1, 2, ..., M:
    初始化状态 s（预处理后的 4 帧堆叠）
    for t = 1, 2, ..., T:
        with probability ε:  // ε-贪心探索
            a = random action
        else:
            a = argmax_a Q(s, a; θ)
        执行动作 a，观察奖励 r 和下一状态 s'
        s = preprocess(s')  // 堆叠最近 4 帧
        将 (s, a, r, s') 存入 D
        if 足够多样本:
            从 D 中采样小批量 {(sᵢ, aᵢ, rᵢ, sᵢ')}
            yᵢ = rᵢ + γ max_a' Q̂(sᵢ', a'; θ⁻)  // 目标网络计算
            对 (yᵢ - Q(sᵢ, aᵢ; θ))² 做梯度下降
        每隔 C 步: θ⁻ ← θ

DQN 的后续改进：

改进 论文 核心贡献
Double DQN van Hasselt et al., 2015 解耦动作选择与价值评估，减少 Q 值过估计
Dueling DQN Wang et al., 2016 将 Q 值分解为状态价值 V(s) 和优势函数 A(s,a)
Prioritized Replay Schaul et al., 2016 优先回放高 TD 误差的经验
Rainbow Hessel et al., 2017 整合以上所有改进 + A3C + distributional RL

输入预处理的关键：

  • 灰度化：RGB → 灰度，减少输入维度
  • 帧堆叠：将最近 4 帧堆叠为输入，解决部分可观测问题（获取运动信息）
  • 裁剪与缩放：裁剪为 84×84，标准化输入尺寸

4. RoboCup 2D —— 多智能体足球仿真

训练环境

RoboCup 2D Soccer Simulation 是一个多智能体、连续动作、随机性、部分可观测的仿真环境：

  • 队伍配置：每队 11 个智能体（1 守门员 + 10 场上球员）
  • 动作空间：连续（踢球力度/方向、冲刺速度/方向）、离散（转身视角）
  • 环境特点：
    • 随机性：动作执行有噪声（踢偏、跑偏）
    • 部分可观测：视野有限（默认 90°），看不到背身区域
    • 实时性：每 100ms 一个仿真周期，需要在线决策
    • 团队协作：需要多智能体配合
  • 通信限制：队友间通信有带宽限制和延迟

核心问题

问题 说明
连续动作控制 动作是连续的（速度、力度、角度），离散化会损失精度
部分可观测 球员视野有限，需要信息推断
随机执行 动作执行有噪声（不确定性建模）
多智能体协作 11 个球员需要协同攻防
层次化决策 包含战略层（阵型）→战术层（传球路线）→底层控制（跑位/踢球）
对手建模 需要适应不同对手的打法
实时约束 100ms 周期内必须做出决策

对应算法体系

RoboCup 2D 没有单一的”万能算法”，而是采用层次化混合架构，融合了规则系统、搜索算法和机器学习：

三层架构：

┌─────────────────────────────────────────┐
│         战略层（Strategic Layer）         │
│   阵型选择、角色分配、攻防转换            │
│   算法：HFTN、强化学习                    │
├─────────────────────────────────────────┤
│         战术层（Tactical Layer）          │
│   传球路线规划、跑位决策、配合策略         │
│   算法：Decision Tree、MCTS、Q-Learning  │
├─────────────────────────────────────────┤
│         底层控制（Low-Level Control）     │
│   踢球执行、跑位导航、转身追球            │
│   算法：Kick引擎、路径规划、PID控制       │
└─────────────────────────────────────────┘

关键算法模块：

1. HFTN（Hierarchical Finite State Machine / Task Network）

RoboCup 2D 中最广泛使用的高层决策框架：

  • 将比赛行为组织为层次化的任务网络
  • 上层任务分解为子任务，子任务可以有不同实现方式
  • 通过选择函数根据当前局面选择最佳子任务序列
进攻任务
├── 快攻 (Kick and Rush)
│   └── 直接向球门方向大力踢球
├── 传球配合 (Pass)
│   ├── 寻找最佳接球队友
│   └── 评估传球路线安全性
└── 盘带推进 (Dribble)
    ├── 向空当运球
    └── 根据防守调整方向

2. 多智能体 Q-Learning

用于局部协作决策：

  • 每个智能体维护自己的 Q 表或 Q 网络
  • 状态：局部观测（附近队友/对手位置、球的位置）
  • 动作：传球/盘带/射门等高层决策
  • 奖励：进球/失球、控球时间、传球成功率

3. MCTS 在 RoboCup 中的应用

近年来的先进队伍（如 CYRUS 2021 冠军）开始将 MCTS 用于战术决策：

  • 搜索树节点代表比赛状态
  • 模拟使用快速的启发式策略
  • 评估考虑进球概率、控球率、场地控制等指标

4. 底层控制算法

模块 算法 说明
踢球执行 Kick Engine 根据目标位置和力度，迭代计算最佳踢球序列
跑位导航 路径规划 A* / 势场法 / 速度障碍法
身体控制 PID 控制 控制冲刺速度和身体朝向
追球 Intercept 预测球的运动轨迹，计算截球点

强化学习在 RoboCup 2D 中的应用：

RL 在 RoboCup 2D 中主要用于局部技能优化而非全局决策：

  • 传球决策：学习何时传球、传给谁、以多大力度传
  • 跑位选择：学习在特定局面下跑向哪里
  • 防守站位：学习最优的盯人和补防策略
  • 射门角度选择：学习从不同位置选择最佳射门角度

挑战在于：RoboCup 2D 的环境复杂度高、团队协作依赖性强，直接端到端训练难以收敛，因此 RL 更多作为规则系统的补充而非替代。
